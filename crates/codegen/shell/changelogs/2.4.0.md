# Grow 2.4.0 — 2026-10-19

本版本升级会话挂起、任务规划、计划审阅和技能加载。

## 会话挂起与恢复

- 正常退出和更新重启会先挂起所有受管会话及子 Agent 树。默认使用 Ctrl+D 在一秒内连续按两次确认退出；首次按键不改变草稿、队列、当前回合或 Goal，第二次才请求挂起。挂起后重复退出键合并到同一操作，不会强退。
- Ctrl+C 仅保留 composer 清理、局部控件操作和当前回合取消；取消等待期间重复按键只重试取消，不触发退出或挂起。
- resume 重建原会话、任务和等待关系，沿用原 Turn、采样额度和已接纳结果。中断命令保留输出与状态，未知副作用需要核对，不自动重放。
- Goal 和 Workflow 保留业务状态与预算；恢复前统一核对原工作区、模型路由、Agent 来源和写入所有权。
- 恢复等待中的子 Agent 结果时同时消费原完成回执，迟到的同源通知不会重复启动模型 Turn。

## 任务规划

- TODO 由会话持久保存，Task 可选关联一个直接父步骤。父项发生非完成的有效修改时，关联子 Agent 收到变更并自行重规划。
- 支持真实依赖的结构化等待、必需交付验收和带来源的局部摘要。等待不靠模型轮询；完成复核同时用于普通回答、结构化输出和 Goal。

## 计划与技能

- Plan 可以延期审阅，并通过原候选、版本和决定身份恢复；收起页面不等于放弃，查看不产生批准。
- Plan 决定写入尚未确认时，状态查询返回“未确认”。导入会拒绝仍可审阅或待执行的来源审批关系；目标会话须新提交并重新审批，已闭合历史仍可导入。
- Plan 预览和行评论绑定原会话及提交身份；版本变化时旧评论保留为未发送草稿，不自动套用到新计划。
- 用户选择与模型调用共用 `load_skill`。用户原文和整组技能原子发布，首次接纳响应前保护正文；失败或未知提交不会留下半组指令。
- 没有有效挂起 checkpoint 的异常重启会撤下原执行未消费的技能正文；有效挂起继续保留原上下文。

## 稳定性修复

- 普通 MCP 工具遇到传输丢失或超时只返回结果未知，不自动重发；后续明确调用可以重新连接。服务名统一用于合并与运行时身份，同一客户端列表的重名输入会被拒绝。
- MCP 禁用工具与 timeout/meta 策略可以随可信配置刷新；已接纳调用保持原 deadline，子 Agent 保持继承能力边界。
- 修复 Plan 访谈部分回答的自由文本丢失、旧 Workflow clear 覆盖新状态、未知 turn 结束原因误标成功，以及搜索缓存自愈对其他 root 的干扰。
- 询问启动按来源与询问 ID 持久接纳，相同重试不重复生成启动审计或提示；启动期间的并发查询不再将活跃询问误判为来源重启，接纳期间仍可取消。模型 `ask_session` 的空白询问 ID 按未提供处理并生成新 ID；非空值和外部协议入口继续严格校验。
- 后台压缩取消保留原 worker，并在挂起或退出前完成用量结算，避免 Goal 关闭与 worker 退役互相等待。
- 旧父子会话链只有在全部成员过期、结果交付闭合且无活动 writer 时才联合回收；中途退出后继续同一回收决定，单独删除会拒绝拆散结果链。
- 人工问询、权限请求和 Plan 审批记录不含正文的等待边界，Replay 单独处理已确认的挂起离线时间。离线读取按精确身份与摘要检查用户显示内容、turn 终态和已登记的 Workflow/控制投影缺口。
- 修复 headless 不重放历史时冷恢复事件序号不足的问题；普通历史和 rewind 隐藏行已占用的事件 ID 均不会被复用。

## 采样修复

- 识别含图片请求中的中文 text-only 能力拒绝，沿用已有图片描述恢复。
- 图片能力拒绝按实际 model、backend、endpoint/query 路由记录；同一路由的不同别名共享状态，路由变化后独立判断，辅助视觉请求避免递归调用已拒绝图片的运行时。
- 冷恢复复用同一有效图片来源的已完成中性描述，即使辅助配置已关闭或其他输入推进了修订；继续核对来源、prompt、完成证据和当前投影身份，拒绝未来修订。
- 图片恢复随所属回合取消而停止；取消不会继续触发 OCR、后续图片组或主请求。补齐 OCR、持久化确认和图片恢复生命周期回归。
- 接受 Chat usage 中缺失或为 null 的可选 token 明细，保留可信总量。

MCP 多轮交互暂缓，现有能力门禁保持关闭。

本版更新会话、Control 和 Workflow 存储格式，不提供旧格式迁移。
