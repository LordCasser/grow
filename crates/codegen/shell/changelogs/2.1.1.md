# 2.1.1 — 2026-09-01

2.1.1 修复 Session 恢复、Behavior 切换与后台 Workflow 生命周期中的几处边界错误，不提升持久化 schema 版本。

## Session 恢复诊断

- `session/load` 现在会在解析未来格式的具体字段前检查版本 envelope。Session format、Timeline schema、Session Control architecture、Goal architecture 与 Sideband schema 不兼容时，错误会明确给出首个不兼容组件、持久版本和当前版本，并提示该 Session 无法恢复、需要新建 Session。
- 普通损坏或缺字段仍与版本不兼容区分，返回具体的无效数据原因，不再统一退化为模糊的文件系统读取失败。
- Workflow run manifest 是可由权威 Timeline seed 重建的运行投影；单个 manifest 无效时仍按既有设计修复或跳过，不把整个 Session 判为不可恢复。Trajectory v3 是查询输出 schema，不参与 `session/load`。

## Behavior、Workflow 与 Rewind

- Normal/Clarify 的 turn 已经完成用户可见输出、但仍处于 terminalization 边界时，Picker 可以立即选择 Plan 或 Workflow。旧 turn 保持其 admission 时捕获的 Behavior，新 Behavior 在 terminal fence 后生效。
- Pager 在结构化 Behavior projection 到达前，会区分“能力目录尚未到达”和“已知命令目录不包含 Workflow”，不再因 tool snapshot 仍为空而错误显示 Workflow 支持。
- 活跃 Workflow run 现在会让所属 Session 保持 resident；客户端重连或空闲回收不能在后台运行尚未结束时卸载 actor。
- `grow/rewind/points` 与 `grow/rewind/execute` 统一经过 `session/load` 并发栅栏。Rewind 与重连恢复并发时会等待 Session 发布，不再误报 `session not found`。

## Subagent

- delegated task 的 child prompt 统一使用 User origin 与 User turn identity，消除输入 admission 与 `TurnStarted` 身份不一致导致的 `turn_boundary_persistence_failed`。

## 兼容性

- Timeline schema 仍为 v24；Session format、Workflow run manifest、Sideband schema 与 Trajectory schema 分别保持 v6、v6、v6、v3。
- 本版本不增加旧 schema 兼容层；检测到不兼容时会 fail closed，并引导创建新 Session。
