# 1.1.3 — 2026-08-03

Grow 1.1.3 收紧了 BYOK 模式下的模型参数边界，并补齐图片与扫描型 PDF 的辅助视觉阅读路径。

## 图片与 PDF 阅读

- `read_file` 返回普通图片或渲染后的 PDF 页面时，若配置了
  `[models].image_description`，Grow 会使用该 provider catalog 模型生成文字描述，再把描述作为
  工具结果交给当前会话。
- 未配置辅助视觉模型时，图片仍作为多模态工具结果直接交给主模型，不引入隐式模型路由。
- 显式辅助模型解析失败、请求失败或返回空内容时，会产生可见文字错误，不会静默换回主模型。
- 扫描型 PDF 的多页图片会在同一次辅助请求中完整传递；PDF `format="text"` 和用户消息附件不受
  该设置影响。

```toml
[models]
default = "primary/main"
image_description = "vision/describe"

[provider.vision.models.describe]
name = "Vision model"
context_window = 128000
```

## BYOK 采样参数

- 图片描述、会话标题、会话压缩、懒惰分类器、记忆重写和命令补全不再写死
  `temperature` 或输出 token 上限。
- 模型目录不会在 reasoning effort 未配置时猜测最低档位；Auto 分类器也不会默认发送 `low`。
- 显式请求覆盖、模型级配置和 `[models]` 全局配置仍然有效；三者都未提供时，Grow 省略对应字段，
  由上游 LLM 服务选择兼容默认值。
- Messages 协议要求的 `max_tokens` 等必需字段仍由协议适配层提供，不属于功能层采样偏好。

这修复了部分模型只允许 `temperature = 1`、不接受 reasoning effort，或拒绝特定采样字段时的
HTTP 400 错误。

## Auto 分类器配置

Auto permission classifier 可以独立选择模型和 effort：

```toml
[auto_mode]
enabled = true
classifier_model = "provider/classifier-model"
reasoning_effort = "low"
prompt_type = "full"
classify_timeout_ms = 30000
```

- 省略 `classifier_model` 时继承当前 session 模型。
- 专用模型无法从 provider catalog 解析或凭据不可用时，回退到 session 模型。
- 显式 `reasoning_effort` 同样作用于回退路径；如果不能保证两个模型都支持，建议省略，让模型配置
  或上游服务决定。

## Architecture

- 图片读取只在 typed `ReadFileOutput` 的 tool-result chokepoint 决定主模型多模态路径或辅助描述
  路径，用户附件保持独立。
- 内部功能不得拥有隐藏采样偏好；请求、`SamplerConfig`、上游默认构成唯一的参数优先级链。
- 详细约束见 `crates/codegen/shell/docs/architecture/image-reading.md` 和
  `crates/codegen/shell/docs/architecture/byok-sampling.md`。
