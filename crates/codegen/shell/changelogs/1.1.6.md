# 1.1.6 — 2026-08-11

Grow 1.1.6 将子 Agent 的静态工具裁剪重构为动态能力与独立权限体系：能力上限、当前授予和
真实调用权限成为三个明确层次，子 Agent 可在任务运行中申请原生 Execute、Read/Write 或单个
MCP server，但任何申请都不能突破 Agent、会话、Behavior、Goal、递归深度、插件信任与 MCP
继承共同形成的硬资格边界。同步完成的 TUI、ACP、leader 与 MCP authority 改造，使嵌套、多
客户端和热更新场景沿同一安全模型工作。

## 子 Agent 动态能力与独立权限

- `[subagents].permission_mode` 新增 `auto | ask | always-approve | follow`，默认 `auto`；所有
  层级子 Agent 使用同一全局策略，但不继承父会话的临时记忆授权。
- 新增仅对子 Agent 可见的 `request_tool_access`。每次申请一个 native Execute、native
  Read/Write 或 MCP server，并携带当前任务必须使用该能力的目的；结果明确区分
  `granted`、`already_granted`、`denied` 与 `unavailable`。
- `capabilityMode` 只决定启动授予，不再破坏性删除 ToolBridge。模型采样与调用分发分别按
  child session 的内存态 grant 过滤，获批能力从下一次采样出现，伪造调用仍会在分发前被拒绝。
- 能力批准只负责暴露工具；后续 Shell、Edit 与 MCP 调用继续走同一个权限管理器。未知工具和
  未分类工具保持 fail closed，Execute 不隐式授予 Task/Workflow，Read/Write 与 Execute 互不包含。
- `explore` 可申请硬资格范围内的 Execute 与 MCP discovery/control；自定义 Agent 只能申请
  authored tool preset/additionalTools 实际包含且未被显式禁止的能力。

## 权限决策、隔离与审计

- 子 Agent 请求携带独立 requested/effective mode、真实 child session、任务描述、purpose、
  classifier transcript 与执行 cwd。`auto` 优先使用显式 classifier model，否则使用主会话模型，
  不使用子 Agent 模型；显式 classifier 不可用时进入用户兜底，不静默换模型。
- auto transcript、审批历史、拒绝预算、Always allow 与 capability grant 均按 child session
  隔离；child 结束时释放，不写项目持久化状态，也不影响父、兄弟、后代或重建后的会话。
- `capability-grant` 复用 PermissionManager 与 PermissionEvent，记录来源 child、请求与实际模式、
  目标、purpose、分类器来源、延迟和结果；能力请求只产生一次真实授权事件。
- managed policy 继续钳制 Always Approve；`follow` 每次动态读取父会话当前模式，但只跟随决策
  模式，不共享父会话临时授权。

## MCP 实时资格与两段式执行

- 子 Agent MCP 目录由父会话当前可见 server、`mcpInheritance`/allow/deny 与 authored ceiling
  求交生成；prompt 和 `search_tool` 显示 server 摘要、工具数及是否仍需授权。
- MCP transport authority 改为实时、带 client incarnation 的继承链。同名 server 被替换时后代
  原地换绑，新增/禁用/移除和 tools-list 变化在采样边界更新；递归后代以直接父会话作为安全上游。
- server grant 与具体 MCP 调用分离：`use_tool`、managed gateway 与直接 MCP 工具在权限等待后、
  真正 dispatch 前再次核对 grant、资格与 transport incarnation，阻止撤权竞态和旧连接复活。

## TUI、ACP 与会话恢复

- ask 请求按真实 child session 路由，权限面板显示 Agent 类型、任务和 purpose；全屏 child、
  Dashboard 与 headless 路径使用相同 requested/effective mode，不再被父会话 YOLO 自动批准。
- 权限、AskUserQuestion 和 PlanApproval 状态归属于具体 AgentView；兄弟子 Agent 可独立等待输入，
  Dashboard 操作按 `(session_id, tool_call_id)` 定位，父 turn 结束或切换模式不会清理 child 交互。
- leader 对 pending child interaction 提供 late-join/reconnect replay 与按 session 的 resolved 通知；
  nested lifecycle、permission 与状态在所有递归层级可路由。
- session resume 通过持久化 ownership 元数据恢复后代目录和路由，保留 source-local event highwater
  并抑制 disk replay/live buffer 重复事件；`follow` child 的显示随父会话当前模式同步。
- mirror fork 不复制可路由的运行中 subagent lifecycle，避免 source/fork 共享 child session ID。

## Deep Research

- 研究规划从固定问题分片改为最多六个自适应研究轴，并为每个轴声明 domain-specific evidence
  target；候选 finding 逐项记录 source support、independent support、conflicting evidence 与限制。
- 验证和综合采用 coverage-driven 选择，不再强制固定论文模板或机械引用每条 packet；报告仍验证
  citation marker、外部链接和图片来源，失败与部分完成路径保留可审计 Markdown artifact。
- 终端结果提供紧凑的调查/验证摘要、核心结论和报告路径，完整长文保持在 session-owned artifact。

## 其他

- 首次启动缺少可用模型时，错误信息同时说明静态 `api_key` 与 `env_key` 两种 BYOK 凭据配置，
  并明确环境变量方式不会把密钥写入配置文件。
