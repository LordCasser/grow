# Grow 2.6.1

2026-11-05

本版本完善子 Agent 的模型选择与 TODO 委派，修复恢复、取消和文件操作中的一致性问题。

## 子 Agent 模型与恢复

- 普通 `resume_from` 支持分别覆盖 model 和 reasoning effort。省略字段时保留来源最后实际使用的选择，派生任务记录最终配置，原任务的历史与结果保持不变。
- 新增 `set_subagent_model`，主 Agent 可以调整自己正在运行的直属子 Agent。控制沿子任务现有 Step 边界应用；`queued` 表示已接纳，后续状态反映实际应用结果。模型切换不扩大子任务权限。
- 子 Agent 列表、标题和生命周期展示保留实际 reasoning effort，便于核对运行配置。

## TODO 委派与目标变化

- 普通模型委派和显式 resume 必须关联当前可执行的父 TODO，关联持久确认后才启动子任务。
- 新增 `todo_read`，Agent 可读取自己的计划，子 Agent 可读取直属父计划。规划上下文按当前请求生成，保留原任务 prompt，不写入聊天历史。
- 编辑关联 TODO 会向子任务交付目标变化通知；删除、取消或替换时省略该 TODO 会要求子任务停止并收尾。已经交付的停止要求不会被重新打开 TODO 撤销。
- 子任务仍按实际命令、结果和交付验收结束。TODO 状态或停止通知本身不表示任务已经完成。

## 恢复与数据一致性

- 修复压缩替换触碰未消费 Skill 加载事实的问题，并保留原有持久化和消费校验。
- Windows 独立读取 child history 时复用正确的目录共享读取能力，避免发布句柄造成共享冲突；读取仍核对目录身份和包含关系。
- 加载后的历史 Workflow 收尾只处理原执行，避免迟到的恢复逻辑终止新启动的通知回合。
- 父级已解除交付要求后，迟到的合法子任务结果仍可按原 canonical 引用完成登记；解除要求不伪造结果或执行终态。
- 工作树删除只清理已证明属于该 checkout 的 Git 注册目录，不把可编辑 gitfile 指针当作删除权限。
- Hunk 拒绝先核对当前磁盘内容，发现外部编辑时返回冲突；统计和 turn 投影只在实际动作成功后提交，多文件批次保留已成功部分。
- 代码导航保留同批次的最终删除事件，清除已删除文件的定义、引用和 metadata，并保持已发布快照不变。
- Sampler 按实际提交任务清理和取消，旧任务结束、panic 或 collect future 释放不会影响复用同一 RequestId 的新任务。
- 取消回合在确认终态后释放自己的采样恢复状态，后续新回合从独立额度开始；挂起后恢复同一回合仍保留原 attempt 额度和期限。
- 工作区发现使用仓库拓扑信息，避免在发现阶段读取配置。

## 接口与升级说明

ACP `grow/tool` 元数据提升为版本 7，增加 `plan_read` 分类。使用闭合工具词表或显式工具清单的客户端和自定义 Agent，需要同步 `todo_read`、`set_subagent_model` 及普通委派的 TODO 关联参数。

普通 resume 继续严格校验来源生命周期、上下文、工作区和当前授权；不满足条件时返回具体失败，不自动改成新任务。此前缺少必要出生或恢复事实的旧 checkpoint 限制保持。

本次以已经验收的成果作为开发里程碑，剩余审计项保留在 [backlog](https://github.com/LordCasser/grow/blob/v2.6.1/openspec/backlog.md)，未将它们计为本版本已修复。
