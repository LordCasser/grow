# 1.1.4 — 2026-08-05

Grow 1.1.4 重构了 Goal/Turn 生命周期：验证、规划与总结改为后台 stage 执行，turn 终结收敛为
单一权威并引入恢复 watchdog，彻底修复 Goal 执行期间回复卡死、界面阻塞和 planner 无限循环；
verifier 运行期间的发送窗口被统一封堵，任何发送尝试都会得到明确提示而不是静默失效。

## Goal 验证不再阻塞界面

- verifier / strategist / summarizer 从 mailbox 内联执行改为后台 GoalStage（effect 化）：
  验证进行时界面与输入完全可用，不再需要 clear 恢复。
- turn 终结统一为单一 finalizer：PromptResponse 与 TurnCompleted 合并为一次原子提交
  （first-wins），终止状态机收敛，消除双 finalizer 竞态。
- 恢复链 watchdog：Submitting 2s / Running 30s 超时自动探测卡死的终结状态并恢复，只补发
  未确认的状态，绝不伪造终结。

## Planner 稳定性

- 计划产物校验宽容化：checklist 缺失仅作为诊断信息，不再打回只改代码的计划 —— 修复 Goal
  启动后反复生成 plan writer 的无限循环（根因之一）。
- 计划 writer 的 spawn 准入在规划开始前打开，取消行为不再关闭准入；planner 增加单飞互斥，
  并发规划只保留一个；planning latch 在过期 lease 上不再泄漏。
- 计划产物为空或发布失败时暂停 Goal 并说明原因，不再静默重试。

## 验证期发送保护

- verifier 判断 Goal 完成期间，所有发送入口统一拦截：普通消息、send-now（Ctrl+Enter /
  空回车）、队列行发送、编辑保存与队列 drain；统一提示
  `Goal is verifying; please wait before sending.`，消息保持排队、草稿保留，验证结束后
  自然发送。
- 拦截在 dispatch 边界对四个发送族（plain / send-now / interject / drain）统一兜底，
  非 Goal 场景行为完全不变。
- 队列行在验证期间显示 `⏳ verifying` 标记，解释空回车为什么不发送。
- Goal Active 时 send-now 统一作为 mid-turn steering 注入（提升 autonomy generation），
  系统事件明确标记为非用户输入。

## Goal 中断面板与 round 采纳（重新发布补充）

- Goal Active 时 Ctrl+C / Esc 打开 Goal 中断面板，显式三选：**Pause goal**
  （暂停 Goal，subagents 继续）、**Stop this turn only**（仅停当前 turn，
  Goal 保持 Active）、**Stop turn + subagents**（连子代理一起停）；无静默默认
  值，也不受 legacy `cancel_subagents_on_turn_cancel` 偏好影响。无运行中 turn
  （验证/规划/间隙）时只提供 Pause goal。
- Esc 仅关闭面板，不再触发任何取消 —— 修复二次 Esc 会走旧取消路径把父 turn
  一并取消的 bug。
- 只有显式选择 "Pause goal" 才会暂停 Goal：`pause_goal` 意图贯穿
  pager → ACP `pauseGoal` meta → shell cancel 管线（`maybe_auto_pause_goal_on_cancel`），
  其余任何取消（普通 Esc/Ctrl+C、仅停 turn、子代理 teardown、生命周期关闭）
  都保持 Goal Active，下一条输入即可继续。
- Goal round（`goal-summary-…`）现在作为普通 Running turn 被 pager 采纳：
  显示 turn 状态行与耗时/计数，round 期间 Enter 排队（服务端 FIFO）、send-now
  作为 foreground steering；移除了 synthetic-turn 停车/放行门，不再出现
  "Sending…" 卡死。
- 修复 goal stage 后台执行（session Idle）期间 goal chip spinner、已用时钟、
  tab 标题 spinner 与 dashboard 行动画停摆的问题：tick 与 redraw 统一到同一
  动画判定（`agent_surface_animating`），dashboard 行分类与 leader roster
  Working/NeedsInput 均驱动刷新。
