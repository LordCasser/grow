# 2.0.0 — 2026-08-26

Grow 2.0.0 是一次不保留旧 runtime 兼容层的架构重构。

## Timeline 与上下文

- Timeline schema v20 makes image projection consume the exact ordered
  `Reasoning` and `BackendToolCall` carriers from the paired Responses output
  and replace them with protocol-neutral text. Completed compaction summaries
  also lose exact managed image references while retaining the rest of their
  text. Earlier Timeline schemas are rejected.
- Session 以 Timeline 为唯一事实源；Control、Surface、Sideband、压缩、回忆和图像替换共享稳定因果坐标。
- Timeline schema v20 同时包含 notification `Dismissed` 终态、subagent 直接安全父级以及 image tool-call 参数的不可逆 shadow，并拒绝旧日志，不提供兼容投影。Behavior/Goal 等运行控制状态以原子 Control 事实持久化。
- Auto-compaction pre-prune 是唯一 ToolResult 减载路径。请求拷贝修剪、turn-age 清理和系统头改写已删除。
- Context recall 同时绑定当前需求与历史证据；Sideband 强制预算、尝试次数、模型路由和结构化输出契约。
- 非多模态模型触发的图片转译通过 Sideband 产生不可逆 ImageShadow；关联 ToolResult、Assistant content/tool-call 参数及同响应 Reasoning siblings 会被同一投影原子消费，图片源路径不会进入辅助模型。原图只作为 Timeline 证据保留，后续模型切换、resume、recall、fork 与 rewind 均不会让图片重新进入模型视图。
- fork、resume、copy 在取得 Surface 前统一校验 Timeline、prompt blobs 与全部 Sideband 来源证明；图片描述的辅助请求也不会收到本地 asset envelope。

## Behavior、Goal 与授权

- Agent Role、Behavior 和 Permission 是三条独立轴，切换任意一轴不会暗中改变另两轴。
- Goal 是一个用户可修改、暂停、重启和清理的长期目标。continuation 首先审计整体完成状态，再使用
  普通 task/todo 执行小步。旧 planner/verifier、Markdown board、Goal task type 和 finalization turn 已删除。
- Goal turn 的 mutation authority 绑定 prompt、Goal id、definition revision 与 active lifecycle；token 记账、提醒、上下文重投影和压缩产生的 Control checkpoint 不再使同一 turn 的 `update_goal` 自我失效，完成或阻塞终态不会陷入 continuation 活锁。
- runner 完成后 foreground 在 Timeline terminal 与客户端终态完成持久化前保持 `Settling` fence；首条 Goal objective 不会再让 continuation 的 `TurnStarted` 越过仍活跃的 user turn。Goal 自动停止同时写入精确 prompt tombstone，迟到 child admission 不能复活已终止工作。
- Plan/Goal lifecycle tool 是 provider batch 的状态屏障；同批只执行第一个控制调用，其余调用统一闭合后在新状态下重新采样。
- Deep Research 由 builtin extractor version-managed 到 `~/.grow/workflows/deep-research.rhai`，作为普通 User workflow 由统一 Registry 扫描；extractor 每次启动幂等核验受管文件，同版本 marker 不再掩盖缺失文件。不再有 Builtin scope、Behavior 或重复的私有 Registry/Run 机制。
- 子 Agent 的实际能力是请求模式与直接父级授权上限的交集，运行时授权不能扩大后代权限。
- nested Task 的生命周期可归并到根 Session，但恢复权限按不可变的直接安全父级检查；兄弟 child 不能互相恢复上下文，模型也不能按 child id 取消 Workflow 私有子 Agent。

## Runtime、Workflow 与 Trajectory

- Shell actor 和 Pager 重新划分 session facts、effect、queue、activity、terminal settlement 与渲染所有权。
- 已保存 Workflow 的动态命令将同步 Rhai 预检放在 Tokio blocking domain，不再在 async worker 中调用
  `blocking_recv()`。预检依然发生在 Run 注册之前，并保留 Behavior admission 与 Definition 快照约束。
- Workflow 动态斜杠命令只由已保存的 Project/User Definition 生成；同名 session 编辑草稿继续显示在 Workspace，但不再隐藏或阻断保存 Definition 的命名启动。
- Workflow Run 冻结完整的无 credential、Task-selectable catalog sampler route，而不是 transport/effort 两张窄表；热更新删除或修改模型不会改变既有 Run。敏感 endpoint/header/query 值与 API key 只留在 runtime lease，重启时无法从同一 credential source 安全重建则 fail closed。明确的 `None` 表示关闭推理，不能退化成继承。初始 manifest 使用 writer 的真实 512 KiB encoder 边界在 spawn 前预检；坏 manifest 按 Run 隔离恢复。Session 模型切换同样以带 revision 的原子 route 提交；catalog reload 在 mailbox 内顺序应用，busy session 合并到最新 generation，并且等待 ACK 时不持有全局 publication lock。
- task/loop/monitor/Workflow reminder 只引用实际注册的输出、轮询与读取能力；能力缺失时提供有界内联结果或真实 artifact 路径，不再发明不存在的工具名。
- Trajectory 为长会话提供 turn/step 聚合、因果导航、过滤和按需展开。重复的流式 phase 事件不再写入 Timeline。

## 发布契约

- GitHub Release 是唯一官方二进制渠道，覆盖 macOS、GNU/musl Linux、Windows、Linux riscv64 和 OHOS arm64。
- 所有正式构建显式启用 `release-dist` feature；OHOS 保持关闭默认 jemalloc，并显式启用
  `release-dist,sandbox-enforce`。常规目标固定 Rust 1.93.1；OHOS 固定官方 Harmonybrew core commit，并使用其中可验证下载的 OHOS host Rust 1.98.0 bottle。
  riscv64 与 OHOS 均应用完整 RELRO/NOW/noexecstack 链接硬化。
- Release 发布 `SHA256SUMS`，内置 updater 必须在解压和执行前校验资产。缺失、重复或不匹配的 checksum
  均会使安装失败。同源 checksum 不是发布者签名；每个平台归档另由官方 workflow 通过 OIDC 生成
  GitHub Artifact Attestation，作为 publisher provenance。
