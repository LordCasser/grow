# 1.1.11 — 2026-08-24

## Long-term Goal Behavior

- Goal is now one durable objective with explicit `active`, `paused`, `blocked`, `usage_limited`, `budget_limited`, and `complete` states. It no longer persists a plan, blackboard, task graph, planner lease, verifier round, or finalization phase.
- An active Goal requests a continuation only after the foreground and user-input queue are idle. User input always wins admission.
- Every continuation begins with a completion audit against the full objective. Remaining work is split into ordinary short-lived `todo_write` steps and `task` subagents; finishing a local task list does not finish the Goal.
- `create_goal`, `get_goal`, and `update_goal` are the complete model-facing lifecycle API. The user controls `/goal edit`, `pause`, `restart`, `budget`, and `clear`.
- Goal and Behavior changes share one versioned Timeline Control snapshot. Create, edit, restart, completion, and clear transitions fail closed on persistence errors instead of exposing half-applied state.
- Goal architecture v7 gives objective/budget edits an independent definition revision and deliberately rejects older snapshots. Provider and compaction request assembly expand only the latest current continuation directive while shadowing superseded copies in place. The retired planner/verifier roles, tools, shared plan types, configuration flags, notifications, and board UI were removed rather than retained as compatibility paths.

## Goal observability

- The Goal detail overlay shows only the durable objective, lifecycle status, token usage, elapsed time, update time, and actionable status message.
- Timeline and scrollback receive lifecycle transitions only; streaming planner/verifier progress and repeated phase ticks are not recorded.

## Delegated authority

- Resolved subagent runtime configuration always carries a concrete initial capability mode. Missing Task/Agent values resolve to `read-write`; nested children receive the lattice intersection with the immediate security parent's initial ceiling, including `read-write ∩ execute = read-only`.
- Runtime grants never enlarge descendant authority, and MCP delegation remains bound to the exact inherited transport incarnation. The obsolete implicit-`all`, subset-check, and widening-rejection mechanisms were removed instead of retained as compatibility paths.
- Child permission routing now accepts only `ask`, `auto`, or `always-approve`. It defaults to independent `auto`; `follow`, parent-mode UI broadcasts, and missing-mode inheritance were removed.

## Context projection

- Ordinary sampling requests now set a fixed-size `prompt_cache_key` from Timeline identity, the latest rewind branch anchor, and backend/base URL/model identity. Ordinary appends retain the key, while fork, rewind, and model-route changes create a new lineage.
- Tool-result load shedding now has one mechanism: auto-compaction `pre_prune` plans an actor-serialized, durable Timeline replacement. The request-copy trim, per-turn age-based hard clear, `[compaction.pruning]`, and their remote settings were removed. Pruning applies its signed Surface reduction to the latest provider token anchor instead of replacing it with a fresh local estimate.
- Image-input rejection now records route-scoped, log-only ImageShadows bound to stable Surface IDs, image fingerprints, and image-description Sideband results. Canonical User/ToolResult images are never rewritten; request assembly applies shadows only for the rejected model route, while another route sees the originals.
- The 50 MiB inline-image limit remains a separate request-copy transport budget after target-model projection. It cannot mutate Timeline or act as a second capability-recovery mechanism.
- Each Behavior selection now records its snapshot and synthetic model context in one Timeline Control event. Surface replay keeps that item at its effective boundary before any output it can condition; later selections append, and Normal writes an explicit reset. The former per-turn system-head replacement and mutable `PromptContext.behavior_instructions` path were removed.
- Behavior transitions now share the foreground-admission mutex and are rejected outside `Idle`, preventing a new protocol from being ordered before late output from the old turn.
- Control contexts emitted by in-turn lifecycle changes stay pending in the Timeline fold until `TurnEnded`; intermediate contexts remain auditable but only the latest becomes model-visible.
- Context recall no longer bypasses retrieval merely because every unloaded causal unit fits the evidence budget. Unrelated queries terminate as local `not_found`, and Sideband parent validation now recognizes the Control events that own live Behavior/Goal Surface items, so those recalls remain replayable after session reload.
- Recall now derives a bounded need context from the atomically frozen current Surface, prioritizing the rolling compaction summary and recent causal units while excluding system/private reasoning and recall-derived exchanges. Sideband attempts reference the exact union of need and archive inputs; every retry is counted against the sideband window, and final commit checks a frozen whole-ToolResult budget.
- Sideband schema v5 records a single request-level admission envelope before any provider call. All auxiliary purposes now enforce the frozen maximum attempt count and actual per-attempt input/output configuration at durable attempt append, with no reader compatibility for older Sideband ledgers.
- Timeline schema v12 includes atomic Control/model-context and ImageProjection facts and rejects every earlier schema instead of maintaining compatibility projections.

## Workflow

- Launching a saved Workflow through its dynamic command now keeps the public Workflow admission gate while running synchronous Rhai preflight in Tokio's blocking domain. Launch args are parsed once for both preflight and the immutable Run snapshot; validation errors, Definition hash drift, and blocking-task failures all return before a Run is created.
