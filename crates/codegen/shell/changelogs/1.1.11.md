# 1.1.11 — 2026-08-16

## Goal 规划：结构化提交、逐项反馈与续接重试（修复 planner 无限重启）

- 根因修复：此前 planner 需要一次性返回逐字节精确的 Markdown 黑板，格式校验失败被当作瞬时故障盲重试——每轮重试都重新做完整工作区探索且不携带失败原因，直到 3 次失败暂停，表现为 goal 设置后 planner subagent 反复重启。
- planner 现在通过 `submit_goal_plan_section` 分段提交结构化计划（`plan_tasks` / `goal_acceptance` / 可选 `open_gaps`）；任务 id（T1/T1.1…）、缩进、章节与全部 Markdown 由宿主拼装并回读校验，`finalize_goal_plan` 提交黑板并进入执行。
- 每段提交返回逐项结构化错误（精确到条目路径），planner 在同一会话内修正重交；段校验失败不计入失败次数。
- planner 未完成或基础设施失败时，后台重拉改为 resume 上一任 planner 子会话（保留工作区探索上下文、已接受分段与失败原因），不再从零盲试；3 次重拉类失败仍有 Paused 上界，且暂停消息携带可行动原因。
- 安全边界：提交工具（新增 `ToolKind::GoalPlanSubmit`，只读类）仅注入 planner 角色子会话；verifier 与 worker 子代理不可见。分段 staging 不持久化，编辑 / 重规划 / 清除 / 暂停 / 预算耗尽时失效。
- 持久化 schema 不变（Goal architecture v5），升级不影响进行中的 Goal。

## 内部质量

- 新增 `assemble_goal_board`：结构化计划 → canonical 黑板的纯拼装函数，渲染后强制回读既有严格 parser（fail closed）。
- 新增 Tier-3 staging 测试套件（11 用例）：宿主 id 分配、逐项错误、失败续接、3 次暂停上界、迟到 stage 拒绝、replan / 暂停失效等；工具层 fail-closed 三分支与能力矩阵同步扩展。
