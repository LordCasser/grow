# 1.1.11 — 2026-08-24

## Long-term Goal Behavior

- Goal is now one durable objective with explicit `active`, `paused`, `blocked`, `usage_limited`, `budget_limited`, and `complete` states. It no longer persists a plan, blackboard, task graph, planner lease, verifier round, or finalization phase.
- An active Goal requests a continuation only after the foreground and user-input queue are idle. User input always wins admission.
- Every continuation begins with a completion audit against the full objective. Remaining work is split into ordinary short-lived `todo_write` steps and `task` subagents; finishing a local task list does not finish the Goal.
- `create_goal`, `get_goal`, and `update_goal` are the complete model-facing lifecycle API. The user controls `/goal edit`, `pause`, `restart`, `budget`, and `clear`.
- Goal and Behavior changes share one versioned Timeline Control snapshot. Create, edit, restart, completion, and clear transitions fail closed on persistence errors instead of exposing half-applied state.
- Goal architecture v7 gives objective/budget edits an independent definition revision and deliberately rejects older snapshots. Provider and compaction request assembly expand only the latest current continuation directive while shadowing superseded copies in place. The retired planner/verifier roles, tools, shared plan types, configuration flags, notifications, and board UI were removed rather than retained as compatibility paths.

## Goal observability

- The Goal detail overlay shows only the durable objective, lifecycle status, token usage, elapsed time, update time, and actionable status message.
- Timeline and scrollback receive lifecycle transitions only; streaming planner/verifier progress and repeated phase ticks are not recorded.

## Delegated authority

- Resolved subagent runtime configuration always carries a concrete initial capability mode. Missing Task/Agent values resolve to `read-write`; nested children receive the lattice intersection with the immediate security parent's initial ceiling, including `read-write ∩ execute = read-only`.
- Runtime grants never enlarge descendant authority, and MCP delegation remains bound to the exact inherited transport incarnation. The obsolete implicit-`all`, subset-check, and widening-rejection mechanisms were removed instead of retained as compatibility paths.
- Child permission routing now accepts only `ask`, `auto`, or `always-approve`. It defaults to independent `auto`; `follow`, parent-mode UI broadcasts, and missing-mode inheritance were removed.

## Context projection

- Ordinary sampling requests now set a fixed-size `prompt_cache_key` from Timeline identity, the latest rewind branch anchor, and backend/base URL/model identity. Ordinary appends retain the key, while fork, rewind, and model-route changes create a new lineage.
