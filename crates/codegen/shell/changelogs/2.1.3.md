# 2.1.3 — 2026-09-03

2.1.3 提升三种模型流端点的容错性，并修复协议异常、图片输入、项目规则发现和 Windows 长路径导致的 Session 可用性问题。

## 模型流与 Session 恢复

- Chat Completions、Responses 和 Messages 统一处理未知顶层扩展事件，例如 `ping` 或供应商自定义事件；可安全忽略的扩展不会污染对话或打断正常流。
- 对已知事件的结构、终态、工具调用身份和完整 JSON 参数执行严格校验。真实协议错误仍会失败并保留诊断，不会被伪装成正常完成，也不会执行半截工具调用。
- 协议失败在当前回合内原子隔离，已有健康的 Session 历史、工具结果和 usage 保留；后续继续对话、切换模型、重启恢复都可以继续使用同一 Session。
- 可恢复的 provider 错误不再在 TUI 中产生噪声提示；只有当前任务最终无法继续时，才显示一次标准的重试耗尽样式错误。

## 输入、规则与项目文件

- 图片输入使用受限的持久化 blob/manifest，失败输入可以显式重试，避免大图片或坏输入污染整个 Session。
- 文件工具和项目 cwd 会动态发现作用域内的 `AGENTS.md`，并在读取结果交付后确认，支持失败重试及边界限制。
- 计划文件和代码索引缓存统一使用与 Session 相同的有界 cwd 编码。

## Windows 长路径

- Session 创建、分叉和导入的临时目录不再拼接最终 Session 名称，避免合法的长名称在追加 UUID 后超过文件系统组件上限。
- 超长 Session 写锁名使用稳定哈希，删除隔离目录也使用固定长度临时名；正式 Session 名称和历史存储位置不变。
- 长项目路径、中文/空格路径、UNC 路径以及超过传统 MAX_PATH 的构造数据均有回归测试覆盖。

## 兼容性与验证

- 不改变 Timeline、Session、Sideband、Trajectory 和输入 manifest schema 版本。
- 所有新测试使用构造数据和本地 Mock，不上传真实 API 请求或密钥。
- Shell 单元测试 3,655 项通过，Pager 单元测试 7,045 项通过；长路径专项测试通过。Windows 原生构建由发布矩阵执行。
