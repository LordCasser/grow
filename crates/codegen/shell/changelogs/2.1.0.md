# 2.1.0 — 2026-09-01

> [!WARNING]
> 2.1.0 将 Timeline schema 从 v21 升到 v24，并将 Workflow run manifest 升到 v6。Grow 不迁移旧数据：旧 Timeline 或旧 Workflow manifest 会返回明确的版本不兼容错误；需要继续工作时请创建新 Session。Session format 仍为 v6，Sideband 仍为 v6，Trajectory 仍为 v3。

2.1.0 不是一次单点功能更新。它把本地多 Session 协作、Hook 生命周期、HumanIntent admission、Plan/Goal/Workflow 控制流和采样恢复都收进同一套“先提交事实，再允许副作用”的边界里。最直接的结果是：Plan 获批后会在同一个 Turn 自动开始执行；Hook、Workflow 和跨 Session 询问在崩溃、重连与并发条件下都有可解释的唯一终态。

## 本地 Session 协作与 ACP

- 同一 OS 用户、同一 `GROW_HOME` 下运行的 primary Session 可以互相发现和询问。进程通过 owner-private 本地 manifest、incarnation、heartbeat lease 与本地 IPC 识别彼此；过期 lease 会回收，身份冲突会隐藏，不开放 TCP 服务。
- 新增 `list_active_sessions` 和 `ask_session` 工具，以及 `grow/coordination/list`、`grow/coordination/ask`、`grow/coordination/cancel` ACP 扩展。询问具有 typed progress、timeout、cancel、unavailable 与 failure 终态；断线只在同一 inquiry identity 下恢复，不复制请求。
- 目标 Session 从已提交 Timeline 冻结上下文，只执行一次无工具 Sideband 请求。它不能借询问运行工具、编辑工作区或自动恢复 Workflow。跨 canonical workspace 询问必须由在线目标 UI 做一次性批准；拒绝、超时或 UI 不在线都会 fail closed。
- ACP stable v1 stack 迁移到 Rust SDK 2.0.0。MCP 仍是 client-only 使用方式；本版本没有引入 `rmcp/server` feature 或 Grow 作为 MCP server 的运行场景。

详细语义见 [Subagents 与本地 Session 协作](https://github.com/LordCasser/grow/blob/v2.1.0/crates/codegen/pager/docs/user-guide/16-subagents.md) 和 [ACP Agent mode](https://github.com/LordCasser/grow/blob/v2.1.0/crates/codegen/pager/docs/user-guide/15-agent-mode.md)。

## Hook 生命周期与输入 admission

- 15 类 Hook 事件全部进入 Timeline。`Triggered` 冻结 handler 计划，执行项必须经过 `RunStarted → RunFinished`，未执行项以 typed `RunSkipped` 闭合，最后才允许提交 gate-specific `Completed`。恢复只会把已开始但未闭合的 run 标记为 outcome unknown，不重放可能已经产生副作用的 handler。
- file handler 与 client callback 现在是一条严格有序的策略链。只有轮到自己的 handler 才能启动；首次明确 deny、stop block 或 force-stop 后，所有后序项都记为 `skipped(prior_block)`，不会出现回调已经产生外部副作用、随后才被标成 cancelled 的窗口。
- Stop continuation 达到 8 次上限时仍记录完整 occurrence；匹配项以 `PolicyDisabled` 跳过，聚合结果为 `AllowStop`，但外部 Hook 不再执行。
- HookExecution、阻断 annotation、Trajectory 与 diagnostics 均从已完成的 `HookLifecycleProjection` 生成。重连时重新查询 Timeline，Pager 按 `occurrence_id` 去重；瞬态 transport 不再成为第二事实源。
- 真实用户输入先以不可变 artifact 和 `InputSubmitted` 落账，再运行 `UserPromptSubmit` gate、提交 admission 决定并选择唯一 queue/steer/idle 路由。被阻断输入不会进入 Surface、Turn、队列或 interjection；同一 `input_id` 也不会因重仲裁重复 admission。

Hook 配置和严格短路规则见 [Hooks 用户指南](https://github.com/LordCasser/grow/blob/v2.1.0/crates/codegen/pager/docs/user-guide/10-hooks.md)。

## Behavior、Workflow 与 Pager 闭环

- Plan 审批改为显式 `ResampleStep`：批准或 Request changes 会结束当前 Step，但不会结束 Turn。新的 PlanPhase context 与工具权限激活后，provider 在同一 Turn 继续采样。没有存活 Turn 时，持久化 handoff receipt 会唤醒内部 Turn，恢复不再依赖内存伪用户消息。
- Plan approval feedback 只进入 PlanPhase 一次；Pager 不再通过额外 Interject 重复评论。`plan_control complete` 必须携带非空 `report`，该工具结果就是唯一最终报告，随后明确结束 Turn。
- Goal 的 incomplete usage、pause/exit 和 provider admission 共享终止栅栏。即使 incomplete 已经记录，只要当前没有活跃 Step，也必须停止 foreground，不能把 User-origin Goal Turn 当普通 Turn 继续采样。
- Workflow 将 `await_user` 与普通 pause 分开，并持久化 `Completion`、`AttentionRequired` 或 `None` handoff。自然完成、失败、预算耗尽和中断会产生 completion；`await_user` 只提示所需操作和明确的 resume 命令；显式 pause/stop/cancel 不再生成重复聊天回合。通知以有上限的指数退避持续投递，直到 receipt 已提交或 mailbox 关闭。
- Behavior availability 的展示、确认和最终 admission 使用同一 predicate；control lock 不跨 provider、Pager 或工具 await。Pager 文本草稿可以从本地持久化恢复，临时图片路径不会写入长期状态。

## 采样、恢复与安全边界

- provider-neutral 采样保留 typed 与 raw stop reason；`Length + text` 继续同一 Turn，完整 tool call 即使伴随 Length 也只执行一次，不完整 reasoning/tool call 不会被提升为可执行事实。context overflow 走一次明确 compaction 恢复，仍超限则产生 typed terminal。
- 只允许在没有任何不可逆输出时重试 provider 请求。`pause_turn` 不再注入 synthetic prompt，replay 不复制 assistant、tool 或 HumanIntent 事实。
- Workflow Timeline seed/lifecycle 成为运行投影的权威来源；sidecar 缺失或损坏不会覆盖已提交终态。Workflow Search 保持 observation-only，Inspect 明确按读写能力处理。
- Hook source 在每个执行边界重新验证 provenance 与 Folder Trust 文件系统身份；MCP server、transport 与 config generation 隔离，socket、`sendmmsg`、`io_uring` 等危险路径继续使用 typed denial。已继承的 connected FD 完整封锁仍是长期 ROADMAP 项，本版本不宣称解决。

- `nucleo` 保持当前 git revision，没有切换到新版本；`third_party` 源码也没有随本轮依赖升级改动。

## Session 兼容性

- Timeline schema：v21 → v24。
- Session Control architecture：v5；Workflow run manifest：v6。
- Session format 仍为 v6，Sideband schema 仍为 v6，Trajectory schema 仍为 v3。
- 不提供旧 Timeline 或旧 Workflow manifest 的迁移/兼容读取。版本不匹配会明确拒绝，而不是尽力恢复成不完整状态。
