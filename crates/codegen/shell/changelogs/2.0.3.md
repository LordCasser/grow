# 2.0.3 — 2026-08-29

2.0.3 是 2.0 系列的上下文压力与 Windows Trajectory 稳定性版本。它降低默认自动压缩触发点，补齐
provider 明确报告上下文溢出时的恢复路径，并修复 Windows 上调试实时 Session 时的目录共享冲突。
本版本不引入新的 Timeline、Sideband 或 Trajectory schema 迁移；从 2.0.1/2.0.2 升级可以继续使用现有会话。

## 更早、更可靠的上下文压缩

- 默认 `auto_compact_threshold_percent` 从 85% 调整为 75%，为 provider tokenizer、隐藏请求封装、工具定义
  和本地 token 估算误差保留更充分的安全空间。`GROW_AUTO_COMPACT_THRESHOLD_PERCENT`、模型级配置与
  `[session]` 全局配置仍可覆盖默认值，既有优先级不变。
- 共享 compaction crate 成为默认阈值的唯一权威来源；Session、Workflow、Subagent、Recap 与权限判断的
  保守输入预算不再各自保留不同的默认数字。
- `ContextPressureUpdated` 现在实时投影到 Fullscreen、Inline 与 Minimal。该更新属于临时 UI 状态，不进入
  Timeline、不可变 Scrollback 或 provider request，因而不会污染模型上下文或 Session 重放。

## Provider 溢出恢复

- 扩充常见 context-window 错误识别。Transport 不再重试完全相同的超大请求，而是把明确的 provider
  溢出证据交给 Session 压缩恢复。
- Provider 明确报告上下文溢出时，其证据优先于偏低的本地估算；若响应携带 context-window metadata，
  Session 同步采用该窗口，否则使用当前配置窗口完成恢复。
- 每个请求投影 epoch 只允许一次立即压缩重投。压缩后仍立即溢出会停止并给出可操作错误，避免无限重试；
  长 Goal turn 在成功模型/工具 Step 后可以开启新的合法恢复周期。
- Model 或 Agent 在 Step 边界切换后，会丢弃旧请求投影留下的待执行压缩触发；新投影重新计算压力，避免
  用新模型或新 Agent 上下文执行旧因果条件下的压缩。

## Windows Trajectory 调试器

- 修复 Windows 上启动 Trajectory debugger 读取实时 Session 时出现
  `Error directory is not a contained regular directory` / OS Error 5 的问题。
- 根因是 Session 发布后的 live writer 句柄在部分重定向或同步文件系统上可能继续持有 `DELETE` access，
  而独立调试器进程原先未声明 `FILE_SHARE_DELETE`，触发 Windows 双向共享检查失败。
- Trajectory 现在使用专用只读 observer capability：共享 namespace mutation，但不削弱 writer capability，
  不进入写缓存，并继续执行 handle-relative、no-follow、reparse-point 拒绝和 regular-directory 校验。
- Root Session、Subagent、Sideband 与 Workflow Run 的 Trajectory 读取统一使用同一观察者语义。

## 验证与分发

- 增加 API 型上下文溢出、压缩后重复溢出、长 Goal 工具 Step 后新恢复周期、实时 context pressure、
  shared-read Session 解析及 Windows DELETE-access 共享冲突回归测试。
- 官方 GitHub Actions 继续构建 Linux、macOS、Windows 与 OpenHarmony 共 10 个发布资产，并生成
  `SHA256SUMS` 与 GitHub Artifact Attestation。GitHub Release 仍是唯一官方二进制渠道。
