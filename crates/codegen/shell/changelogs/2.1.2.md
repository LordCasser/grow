# 2.1.2 — 2026-09-03

2.1.2 修复本地多 Session 协作在发现、重连、崩溃恢复和 Pager 展示上的边界问题，并修复无 token 统计的无限预算 Goal 被错误暂停的问题。

## 本地 Session 协作

- 接收侧询问统一使用结构化审计详情，来源 peer 与 InquiryId 共同组成身份；不同进程使用相同 InquiryId 时不会串联展示或恢复状态。
- `list_active_sessions`、`ask_session` 与重连恢复共享同一在线判定和 Session 存储视图。
- 存活 Session 重载不会误关闭运行中的 sideband；进程崩溃后，排队和运行中的询问各自产生唯一的中断终态，不会重放模型请求。
- 接收侧询问在进行中和完成后都可以像普通工具调用一样展开、收起和查看详情；图片引用不会遮挡问题或回答正文。

## Goal 统计

- 无限预算 Goal 在 provider 未返回 token usage 时不再被自动暂停；预算型 Goal 仍保持保守的 lower-bound 保护，并明确提示需要显式确认或重建预算。

## 命令展示

- Slash 命令统一使用一次调用、一个进行中状态和一个最终结果：排队与等待只更新瞬时状态，成功、失败或取消只提交一次可恢复的终态。重连、Timeline 重放以及迟到的 RPC 响应不会重复追加结果或覆盖已经确认的事实；传输断开且没有权威终态时会明确提示结果未知，不自动重试可能产生副作用的命令。
- 非 Goal behavior 下的 Goal 状态更新不再重复追加生命周期文案，`/goal clear` 只显示一条命令结果。排队中的 Goal 编辑和预算变更保留原始调用身份，应用、拒绝、清除或 Session 关闭后都能闭合到对应结果；普通命令不会吞掉独立发生的 Goal 预算或运行终止事件。
- 手动 `/compact` 在压缩完成、失败或取消时立即显示唯一终态，不再等到下一次模型 Turn，也不会因自动压缩回放而重复。`/memory` 只接受当前请求的查询结果，过期、重复、重连前或已取消的响应不能意外打开浏览器；禁用和读取失败会给出一次可操作提示。
- `/plugins add` 与 `/plugins remove` 将路径变更和注册表刷新合并为一个结果；无法在线刷新时明确说明路径已经修改、需要新建 Session 才能生效。
- 普通命令结果默认折叠命令名、说明和诊断元数据，双击可展开或收起；错误原因和恢复操作仍直接可见。Minimal 模式使用相同规则。

## 兼容性

- 不改变既有 Timeline、Session、Sideband 和 Trajectory schema 版本。
- 本地协调仍限于同一 OS 用户、同一 `GROW_HOME` 和本机进程；Windows 使用共享协议与安全边界，但本版本未在 Windows 主机上执行原生回归。
