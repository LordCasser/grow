# Grow 2.5.1

2026-10-25

本版本保存 Goal 的完整完成报告，修正上下文计数和 effort 同步，并改善全屏侧问结果的查看体验。

## Goal 完成报告

Goal 完成时必须提交非空 `completion_report`，记录结果、完成证据、验证和剩余限制。报告与完成状态一起确认持久化；写入失败不会发布成功状态。点击 `Goal: Done` 可查看 Markdown 报告并滚动长内容，恢复和回放后仍可查看。历史 Goal 没有报告时会明确提示未归档。

工具调用方需要调整：`update_goal(status="complete")` 现在必须同时提供 `completion_report`；`blocked` 不接受该字段。原有完成审查和必需交付门槛仍然适用。

## 上下文计数与技能加载

- 冷恢复时按实际 portable replay 消息估算上下文压力，避免将保存在原始历史中、但不再发送的 reasoning 算入。原始历史保留，真实超出窗口的请求仍会被识别。
- 用户和模型加载技能时，统一使用与请求投影、状态栏一致的上下文计数检查剩余空间，再计入完整新增内容，减少错误拒绝。内容发布、取消和持久化确认继续遵循原有边界。

冷恢复计数仍是请求前估算；工具、schema 等请求开销和 provider 实测用量会通过现有路径补入与校准。

## 终端交互

- 全屏 `/btw` 回答使用更大的覆盖式弹窗；Esc 收起后，双击历史行可在同尺寸查看已保存答案。支持滚动、Markdown、链接和文本选择，输入框保持可用。Minimal 模式沿用原生终端面板。
- 忙碌期间修改 effort，在收到匹配的控制终态回执后立即应用暂存的模型和推理强度状态，避免界面继续显示旧值。

## 升级说明

延续 2.5.0 的 Timeline v27 存储边界，不自动迁移旧格式会话；从更早版本升级前请备份 GROW_HOME，并阅读 [2.5.0 升级说明](https://github.com/LordCasser/grow/blob/v2.5.0/crates/codegen/shell/changelogs/2.5.0.md)。
