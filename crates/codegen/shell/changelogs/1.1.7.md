# 1.1.7 — 2026-08-12

Grow 1.1.7 将公共 Workflow 从一次性 Rhai 启动入口重构为 Behavior、Definition、Workspace 与
Run 边界清晰的完整工作流系统。用户可以在一个 session 中渐进发现、创建、派生、验证和试运行
多个 Workflow，选择保存到项目或用户范围，并在后续 session 中复用；正在运行的任务继续使用
启动时的不可变快照，不受后续编辑或发布影响。

这是一次有意不保留旧接口兼容性的升级：`Static Workflow` 命名和旧启动式 Workflow Tool 输入
已移除，公共 wire id 继续为 `workflow`。

## Workflow Behavior 与权限边界

- Workflow Behavior 成为 Grow 搜索、创建、修改、校验、发布和运行公共 Workflow Definition 的
  唯一协作协议。Tool 暴露、实际分发、slash 管理和 Grow 发起的文件写入同时校验 turn 捕获与实时
  Behavior，防止中途切换后的陈旧调用。
- Workflow 外只保留 `/workflow [prompt]` 与 `/behavior workflow` 快速入口；`/workflows`、
  `/workflow-run`、已保存 Definition 和可运行草稿的动态命令只在 Workflow 内出现。手工构造的
  隐藏命令仍由 Shell 侧拒绝。
- Grow 不能直接覆盖 Project/User Definition，只能修改 session 草稿后发布；用户在外部编辑器中的
  修改保持允许，并会在下次扫描时重新发现和诊断。
- 离开 Workflow 时仅 Active 公共 Run 要求二次确认。暂停、预算受限和未保存草稿不阻止切换；
  Run 可继续在后台执行，但必须重新进入 Workflow 才能管理。
- Deep Research 继续使用私有 Workflow runtime，不进入公共 Definition、命令、Run 列表或门禁。

## Session Workflow Workspace

- 每个 session 持久化多个临时草稿及 Rhai 文件、唯一显式焦点、来源、当前/基线/验证哈希、发布
  冲突和逐内容哈希的保存提示；草稿随 session 恢复，并随 session 删除。
- “当前 workflow”固定指焦点 Definition。修改已保存 Definition 时自动派生同名 session 草稿，
  编辑、验证和试运行只作用于草稿，原 Definition 在发布前继续可用。
- 新 Workflow 和已保存 Definition 的派生使用稳定 `WorkflowDefinitionId` 与显式
  `WorkflowScope`。Draft 来源改为 tagged `inline`、`file` 或 `definition`，不再混用互斥 optional
  字段。
- 未指定 Workflow 时先判断焦点相关性，再按 `name`、`description` 与 `when_to_use` 搜索 session、
  Project、User 和 Builtin 范围；唯一匹配可说明后使用，歧义交给用户选择，编排变化派生草稿，
  无匹配时创建新草稿。
- 新内容首次成功完成后只提示一次保存；用户明确要求复用或保存时，验证通过后立即选择 Project
  或 User 范围发布。

## 验证、发布与诊断

- Workflow Tool 提供 tagged `search`、`inspect`、`draft`、`validate`、`run`、`publish`、
  `discard` 与 `control_run` 动作。未验证的内容在 Run 前自动 preflight，失败不会启动。
- 发布要求显式选择 Project 或 User，使用原子替换和乐观并发检查；来源在派生后被外部修改时拒绝
  覆盖，不会静默处理重名。
- Workspace 使用 write-ahead publish intent 恢复“目标文件已提交、session 状态尚未提交”的崩溃
  窗口；发布期间出现更晚的外部草稿编辑时保留新草稿并保持焦点。
- Registry 不再丢弃错误文件，统一返回语法错误、meta/文件名不一致、重名、不可信路径、读取错误
  和发布冲突诊断。
- Shell 写入识别覆盖相对路径、符号链接、重定向、`cd`、`pushd/popd`、`env -C`、嵌套
  `bash -c` 与非空格分隔，避免绕过 Workflow Definition 和 Run 快照门禁。

## Workflow Run 与 TUI

- Run 持久化 Definition ID、scope、内容哈希、Rhai 与参数不可变快照；同一 Definition 可同时存在
  多个不同状态的 Run，并使用 `name`、`name-2` 等 session 唯一句柄。
- `/workflows` 统一展示 Definitions、Runs 和 Registry diagnostics。Definition 显示焦点、scope、
  临时/已保存、dirty、validated 与 conflicted 状态；Run 显示来源哈希、状态、阶段和 Agent 进度。
- 裸 `/workflow-run` 打开选择器，不再隐式启动最近 Run；省略管理目标时仅在唯一合法候选存在时
  自动选择。
- 创建、验证、运行、完成与发布回执显示 Definition 状态、来源、路径、Run 句柄和可执行下一步。

## 其他

- 默认 Ask 权限模式现在会与 Behavior 一起显示在 TUI prompt 状态中，不再只显示 Auto 或
  Always Approve。
