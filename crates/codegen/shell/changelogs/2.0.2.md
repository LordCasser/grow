# 2.0.2 — 2026-08-29

2.0.2 是 2.0 系列的 TUI 控制反馈与恢复一致性版本。它不引入新的 Timeline、Sideband 或
Trajectory schema 迁移；从 2.0.1 升级可以继续使用现有会话。若从 2.0.0 或更早版本直接升级，
仍需遵守 2.0.1 已声明的 Timeline v21 破坏性边界。

## TUI 消息与双形态投影

- 引入统一的 UI-only `Notice` 语义，明确区分临时进度、不可变终态与模型上下文。命令结果、控制反馈、
  生命周期提示和 Subagent 状态不再借用 Agent 消息，也不会进入 provider request。
- Fullscreen 与 Inline 共用 retained projection：pending/applying 保留在 Footer 或状态区，终态追加一次。
  Minimal 使用独立的 scrollback-native projection：临时状态只刷新 live region，只有终态越过 committed
  frontier，避免长会话中产生无法修改的状态垃圾行。
- Screen mode relaunch、session load 与 reconnect 都从 Shell 权威状态恢复 current/pending/revision，
  不依赖 Pager 进程内队列；live 与 committed renderer 使用相同的换行、行高和链接宽度计算。

## Model、effort、Agent 与 Behavior 控制

- Shell 按 Session 维护 Sampling、Agent、Behavior 三个独立 desired-state 域。Sampling 始终包含完整的
  `provider/model + effort`；同域连续修改采用 latest-wins，旧目标被覆盖后静默 Superseded，不再排出无效切换。
- Sampling 与 Agent 在 step 边界提交：旧采样及其工具批次先完成，随后 `StepEnded`，再提交最终控制目标、
  必要的 Agent 上下文重投影，最后才允许下一个 `StepStarted`。Root 与 Subagent Session 使用同一协议。
- Agent 切换只使 Agent role、工具、权限、MCP、Skill 与完成约束对应的上下文层失效；Timeline 历史身份
  保持不变，并继续沿用分层上下文组装与 prompt-cache lineage。
- Behavior 保留既有 ownership、确认、Goal/Workflow 互斥和 turn admission 规则，只补齐 latest-wins 与
  revision 防护，不把 Behavior 降格为普通 step 切换。
- Pager 现在明确显示 `current → pending` 和最终 Applied/Rejected 结果。Provider 相同裸模型名发生冲突时，
  始终显示并路由完整的 `provider/model` 权威 ID。

## Resume 与控制反馈修复

- 修复每次恢复 Session 都在 transcript 末尾新增 `Sampling switched ...` 的问题。内部 model/effort 恢复、
  初始化路由与自动恢复继续复用同一原子控制机制，但没有用户 `ControlIntent` 时不再发布 Pending、Applying
  或 Applied UI 事件。
- Pager 对 2.0.1 已经写入 `updates.jsonl` 的历史控制回执进行静默状态水合，不把 replay 当作本次运行中新发生的
  用户动作。如果断线或 `/minimal`/`/fullscreen` 重启前确实存在仍在途的本地控制意图，匹配的最终回执仍会显示一次。
- 同一规则覆盖 Sampling、Agent、Behavior、root 与 child；实时用户切换的成功/失败提示不受影响。

## Subagent、命令与交互整理

- Subagent started 与 completed/failed/cancelled 改为独立不可变事件。模型侧结果保持 exactly-once，主视图
  同时获得简洁终态提示；重放、实时接收和 Minimal commit 使用稳定 event ID 去重。
- 斜杠菜单按用途标注 `SESSION`、`CONTROL`、`RUN`、`VIEW`、`SETTINGS`、`EXTENSION`，同时保留
  BuiltIn、Skill、Workflow、Extension 来源元数据。外部 ACP 命令缺少 Grow 元数据时安全归类为 Extension。
- 保留 alias 扩展机制，但删除所有生产内置 alias。`/undo` 已移除，文件与会话回退只保留语义明确的 `/rewind`。
- Slash/host command 输出使用结构化命令结果和 UI Notice，不再伪造成 Agent 输出或污染模型历史。

## 渲染与可用性修复

- Markdown 中过长的本地文件路径和文件链接显示最后一个可解析文件名，OSC 8/点击跳转仍保留完整绝对目标；
  Fullscreen、Inline 与 Minimal 使用同一宽度规则。
- 修复 CJK 宽字符、多行问题选项和窄终端下的边界裁切；斜杠菜单优先保留用途标签与命令名，再按宽度隐藏来源和描述。
- 清理成功信息借用 error toast、重复 Toast/系统行/命令输出以及历史 System block 等路径，统一 Progress、
  Info、Success、Warning、Error 的展示语义。

## 验证与分发

- 增加 clean resume、reconnect pending intent、root/child control terminal、Minimal committed frontier、命令分类、
  Unicode 宽度和完整链接目标等回归测试。
- 官方发布仍由同一 GitHub Actions workflow 构建 10 个平台资产与 `SHA256SUMS`，每个平台归档继续生成
  GitHub Artifact Attestation。GitHub Release 仍是唯一官方二进制渠道。
