# 2.0.1 — 2026-08-27

> [!WARNING]
> **Breaking release.** Timeline schema v21 deliberately rejects every older session log, including 2.0.0 logs. Active 2.0.0 Workflow Run manifests that do not contain the complete frozen route and Agent delegation contract are also rejected; restart those Runs from their Workflow Definitions. Integrations must treat Shell acknowledgements and Timeline events—not optimistic client state—as the authority for model, effort, Agent, Behavior, and Goal changes.

## Step-boundary controls

- Model, reasoning effort, Agent, and Goal-definition changes now share one actor-owned FIFO. A change submitted during a running turn leaves the current stream and its tool batch untouched, commits immediately after `StepEnded`, and governs the next `StepStarted` and provider request.
- Model catalog reloads publish immutable generations. Reloads are resolved against every earlier queued user selection when they are applied, adjacent busy reloads coalesce to the newest generation, and stale catalog work cannot roll a session back.
- Agent changes rebuild the next step's role context, tool projection, completion contract, MCP inheritance, and subagent filter without reconstructing canonical history or defeating the prompt-cache lineage. The previous Agent's response and tool batch remain owned by the previous Agent epoch.
- Root and exact child sessions expose the same control protocol. Ordinary children receive live catalog updates; Workflow children retain the route frozen into their Run unless the user explicitly changes that exact child session.

## Goal lifecycle and global accounting

- Goal remains one long-lived objective rather than a persisted plan. Unedited continuations receive the completion audit once per turn; an edited definition is atomically installed at the next step boundary so the revised objective is visible immediately without corrupting the active step.
- Goal definition and Behavior transitions can now carry multiple typed model contexts in one atomic Control event. Reactivating or editing a Goal cannot expose Goal Behavior without the matching objective revision, or leave a superseded directive as the only provider-visible definition.
- Control events explicitly retire model-context layers. Leaving or stopping Goal retires `GoalDefinition` authority without deleting causal history, so a later compaction repair cannot resurrect an obsolete objective from a shadowed Surface item.
- Token accounting covers every provider attempt admitted while Goal is active: root turns, descendant Agents, retries, compaction, image description, session-title and other Sideband calls. Paused intervals are excluded; accounting resumes under the same Goal identity after restart. Cache reads remain excluded from the normalized charge.
- A paused, unbudgeted Goal whose provider usage is incomplete can now be restarted explicitly without erasing the uncertainty: the ledger remains a durable lower bound, while any later unmetered attempt revokes that acknowledgement and pauses continuation again. Exact token budgets remain unavailable until the Goal is recreated with an exact ledger.
- Known budget exhaustion and unknown usage close the global provider-admission window immediately, but the lifecycle terminal is committed only after the active `StepEnded`. Idle descendant settlement commits the terminal immediately. Exact zero-token request rejections remain distinguishable from unknown usage.
- Stop, edit, completion, blocking, budget exhaustion, and incomplete-usage pause retire Goal-owned work without blocking the root actor on per-process reap timeouts. Goal runtime ownership includes the definition revision so cleanup from an old definition cannot kill work admitted by its replacement.
- Task, monitor, and subagent receipts carry the exact Goal definition revision captured at admission. Incomplete ownership pairs fail before Timeline or UI publication instead of becoming an invalid revision-zero wake that is silently lost.

## Turn, step, and cancellation causality

- `TurnStarted` is durably acknowledged before any prompt route or external effect. `StepStarted`, provider requests, tool starts and terminals, `StepEnded`, Control transitions, and `TurnEnded` are folded in one causal order; a terminal preemption cannot admit another model step.
- Fresh-session bootstrap is now a common barrier for every prompt origin, including autonomous Goal continuations. A deferred stable prefix must be durably published before the first `TurnStarted`, preventing a later context rebuild from crossing an existing prompt branch.
- Model/Agent/Goal controls are admitted under the same step-control gate as `StepStarted`. Pending controls remain FIFO, and a Behavior terminal cannot jump ahead of an earlier route selection or inherit an error sampled under the prior Behavior.
- Provider-attempt accounting survives steering, retries, Stop, owner-future destruction, and session teardown. First-poll cancellation no longer invents a provider attempt, while a started attempt must settle known or incomplete usage exactly once before another request can overtake it.
- Explicit Stop, in-process owner panic, and process-restart recovery close open request/tool children before `StepEnded` and `TurnEnded`. A panic after an already-durable turn terminal fails closed instead of publishing a second conflicting completion.
- Goal terminal cleanup and subagent drain are detached after the durable lifecycle boundary. The root session continues servicing Stop and usage-settlement messages instead of displaying `Cancelling` for a serial chain of process termination timeouts.

## Compaction and model-facing context

- Compaction operates on causal prompt turns identified by Timeline `prompt_index`, including Goal, Task, notification, Workflow, Plan-resume, and host-command origins. Raw test-only user nodes no longer masquerade as compaction boundaries.
- Automatic compaction runs between model steps. It cannot bypass a queued route/Goal control or a Goal budget fence, and Workflow compaction reinstalls exactly one authoritative Workflow workspace contract after shadowing the summarized range.
- Root and descendant sessions keep independent compaction thresholds, pruning budgets, suppression state, and transaction identity. Sideband result references remain bound to their parent Timeline and cannot cross root/child sessions.
- A strict pre-inference image-capability rejection is accounted as zero usage, allowing the existing Sideband description path to install an irreversible `ImageProjection` and resubmit to a text-only model. Other usage-less errors still fail closed. Once projected, later model, Agent, Behavior, resume, recall, fork, and rewind operations do not restore the original image in the model-facing view.

## Workflow, Agents, and Behavior cleanup

- Saved Workflow dynamic commands keep the public Workflow admission gate while synchronous Rhai preflight executes on Tokio's blocking pool. Reply-bearing host functions such as `agent()`, `parallel()`, and `budget()` no longer panic an async session worker.
- Workflow discovery uses `~/.grow/workflows` and the trusted project-local `.grow/workflows` directory. The bundled Deep Research definition is released through that same user Workflow registry and is no longer a separate Behavior or duplicate execution mechanism.
- User Agents are discovered from `~/.grow/agents` and project-local definitions; the retired singular legacy directory and Persona system are not retained.
- Task, loop, monitor, notification, Goal, Plan, and Workflow reminders use the unified typed prompt-origin path, preserving their existing runtime effects while giving compaction and Timeline one causal boundary model.

## Pager and Trajectory

- Pager serializes control RPCs per root or child session, holds prompts behind Behavior/control acknowledgements, recursively invalidates stale descendant generations on reconnect, and applies late authoritative notifications only after the local FIFO drains.
- Trajectory adopts a neutral shadcn-style light/dark visual system, stronger turn and step grouping, balanced metadata columns, clearer event hierarchy, and stable expandable canonical-event panels.
- Long sessions use layered summaries and lazy event disclosure instead of eagerly rendering every payload. URL session/turn identity is normalized, meaningless internal turn numbers are de-emphasized, and repeated streaming phase ticks are omitted from the Timeline view.
- Question options pad labels by Unicode display columns, so CJK and other wide labels no longer clip the first line of a multi-line description at the panel boundary.
- MCP Servers requests use the Shell-owned strict `McpListRequest` wire shape; the obsolete client-only `cache` parameter is removed instead of being silently ignored.

## Distribution

- Version metadata, updater repository checks, the ten-platform release matrix, asset naming, checksums, attestations, and tag-to-commit validation are pinned to 2.0.1.
- Windows session publication no longer depends on hard links or a handle-relative rename accepted only by some filesystems. Immutable files and the staged session directory use exact-handle, no-replace publication, while the final tree flush reopens existing regular files with the write access required by `FlushFileBuffers`; this removes the deterministic `Access denied (OS error 5)` during session creation without weakening the durability barrier.
- A permanent Windows CI gate now creates and publishes a session, commits the System seed and initial AgentRole, releases the writer, and reopens the Timeline through a second adapter.
- GNU and musl Linux, macOS, Windows, riscv64, and OpenHarmony changes were statically reviewed locally; the official GitHub workflow remains the cross-platform build and publication authority.
