# Pager 链接识别与可见投影

链接目标由内容决定，布局只决定哪些字符可以点击。折叠、截断、换行、滚动不能重新定义目标地址。

## 内容边界

`markdown::plain_url_ranges` 是裸 URL 的共同入口，返回未改写输入中的 UTF-8 字节范围。
Markdown 普通正文扫描、长引用缩略显示（包括表格）与 Pager 的 URL/file-path 检测复用它。
普通正文扫描拼接同一行的全部样式 span；颜色或强调样式本身不是分隔符。

裸链接使用自然语言启发式，不等同于 URL 语法验证：

- Unicode 空白、零宽空格，以及中文句末符号、外围引号/括号形成边界。
- `，、；：` 在路径中按正文分隔处理；在 query/fragment 中保留为数据，除非其后紧接新的 HTTP(S) URL，或位于 token 末尾。
- ASCII 逗号、分号只在 query/fragment 之外、紧邻下一个 HTTP(S) URL 时分割。`?ids=1,2`、`?next=https://…`、URL 列表参数保持完整。
- 普通中文路径和参数继续支持；百分号编码不先解码。ASCII 配对括号、句尾标点继续交给 `linkify` 处理。
- 显式 Markdown destination、工具保存的语义目标不经过这套启发式。其原有 scheme 过滤、相对路径解析与 terminal routing 保持不变。

Markdown 缩略显示还要守住 HTML entity 的边界：候选不能切开 `&nbsp;` 等实体，解码后变成多个 token 的候选也不能取得单一缩略目标。此时保留正文转换，由渲染后的文本扫描识别；不能把实体碎片并入目的地址。

这里有无法从裸文本消除的歧义。例如中文逗号既可能分隔正文，也可能属于真实路径。
需要表达含这些字面标点的完整目标时，应使用显式链接目标或百分号编码；不能靠修改用户原文、自动插空格来解决。

## 来源坐标

`BlockLine.link_source` 记录该行对应的原始逻辑行号、原始显示列范围，以及正文在显示行中的起点。
Markdown 与用户输入在完整内容换行时生成它，而不是在最终 render 阶段从可见行反推。

- Thinking 折叠标题、空白分隔行和省略号没有正文来源；正文链接不能映射到这些合成行。
- 截断 Thinking 保留尾行原来的来源坐标。只复制需要展示的尾部，不复制隐藏正文的样式行。
- 用户输入前缀、续行缩进、截断省略号不占原文列；添加 bullet 时只移动显示起点。
- Markdown 引用续行重复绘制的竖线只占显示列，不能重复计入来源列。
- 插入 Mermaid 等装饰行后，既有正文来源坐标不变。

## 收集与投影

Fullscreen、minimal 的 `EntryRenderer`、`/btw` panel 共用 `collect_content_links`。
先把 Markdown 权威目标投影到可见来源片段，再对这些片段所属的完整逻辑行执行裸链接和文件路径识别。
与权威范围重叠的推断候选整体放弃，即使重叠部分已经滚出视口，也不能把剩余片段重新识别为另一个地址。

没有来源坐标的普通块使用完整缓存行重建逻辑文本，排除非正文 span。
真实换行、选择区域变化、装饰行和已有语义目标行均为边界；不能跨跳过的行连接文本，也不扫描没有前文的软换行续片。
这条兜底路径无法恢复块生产者已经丢弃的原文；会做内容截断的生产者应提供来源坐标或明确目标，而不是要求扫描器猜回原文。

`scan_text_for_links` 的识别结果是逻辑文本中的字节范围；投影阶段才转成显示列、裁剪到正文矩形并缩窄为 terminal 坐标。
因此来源列可以超过 `u16`，但实际点击区域必须处于当前可见正文内。
`LinkOverlay` 同时供 OSC 8 与应用内点击使用，不维护另一份目标解释。
路径只有在单个显示片段完整呈现时才能保留 `SelfResolvingPath`；换行、截断或裁剪得到的片段使用 `Opaque`，不能把半截路径交给 VS Code Remote 的原生路径识别。

## 验证与独立缺口

回归测试检查完整目标和点击范围，不只检查下划线外观：中文分隔、Unicode 空白、样式切分、流式切分、显式链接、长链接缩略、查询嵌套 URL、折叠往返、截断尾部、用户输入缩进、视口裁剪、超长来源列，以及 fullscreen/minimal/`btw` 入口。

`linkify 0.10.0` 对 IPv6 authority 的裸链接识别存在独立能力缺口，本次不更换 URL 解析器，也不添加专门补丁。
