# v1.0.0 之后 Turn/Goal 回归归因与重构结论

本文记录为什么 Grow 的 turn 管线在 v1.1.x 逐渐失去单一调度语义，以及本次 v2 重构如何消除根因。它不是旧行为兼容说明；旧 Goal wire/state/protocol 已明确不迁移。

## 1. 结论

v1.0.0 的主体是 grok-build 到 Grow 的产品、命名和 Behavior 重构。原有 Goal 本来就复杂，但当时还没有形成当前这类多套 turn admission/terminal/adoption 协议互相补偿的局面。

真正让管线混乱的是 v1.1.2 到 v1.1.4 的连续修补：

| 提交 | 当时解决的问题 | 引入的结构代价 |
|---|---|---|
| `7e441060` | Goal 运行中继续接受输入 | 新增 Goal 专用 mid-turn interjection 路径，普通 queue/turn 之外出现第二种输入调度 |
| `abca23e0` | 控制操作不应和模型工作绑死 | 引入 out-of-band control 与 hidden Goal turn，控制面和执行面仍通过 synthetic prompt 互相唤醒 |
| `ca7a29f3` | planner/verifier、terminal recovery 和续作稳定性 | stage actor、terminal finalizer、Goal continuation 同时接入 turn-end，多处 latch/gate 共同决定下一步 |
| `ea5404fc` | Pager 不应把 Goal round 停车为不可见状态 | `GoalSummary` 又被 Pager 当普通 Running turn adoption，Goal status、prompt origin 和 turn ownership 被跨层猜测 |

这些提交分别修复了真实症状，但累积后的系统同时存在：用户 FIFO、send-now cancel/promote、mid-turn interjection、hidden GoalControl、GoalSummary continuation、planner/verifier mailbox、Pager adoption stash、文本 echo skip、first-wins terminal recovery。每一层都在补偿别层的不确定性。

动画冻结也在 `ca7a29f3` 首次形成并随 v1.1.4 发布：原本一次性的 terminal reconcile 被扩成周期性 Running watchdog，并和 `AppView::tick()` 共用一个分支。主 agent 健康等待 subagent 时，watchdog 路径能够反复返回 effect 并跳过动画推进，于是 elapsed 使用实时时钟继续增长，而 spinner/wave 的累计 counter 停住。更早的 grok 实现已经把轮询与动画放在条件 tick 中，存在结构隐患，但尚没有这个会在长等待中持续命中的 watchdog，因而没有同样的稳定复现。

`2dd83021` 调整了分支执行顺序，使 watchdog 与动画都能前进，是正确的止血补丁；它没有移除共享 tick、重复查询、`now + interval` 漂移、render 更新 liveness 和各 surface 私有 counter，所以不属于最终架构修复。

## 2. 原回归补丁为什么不是根治

重构前的在途补丁新增 D1-D6 一类门控：planner/verifier latch、防零 token Goal no-op、用户工作 admission、echo skip 配对、Goal status 推断和 animation select 顺序调整。定向测试能通过，但它们验证的是“多协议碰撞时补丁是否兜住”，不是“系统是否只有一个协议”。

典型问题：

- `GoalSummary`/`GoalControl` 的 origin 由 prompt-id 前缀和零 token 反推；
- Goal continuation 被塞进 `pending_inputs`，既像用户队列项又像调度信号；
- send-now 在某些路径 cancel 当前 turn 并 promote，在 Goal 又尝试解释成 steering；
- Pager 用 `skip_next_user_echo`、trim 文本和 adoption stash 猜一个气泡属于哪个 prompt；
- planner/verifier latch、turn-end 和 Pager Running 状态都能表达“Goal 正在工作”；
- 调整 biased `select!` 分支顺序只能改变谁更容易饿死，不能给 tick 延迟一个上界。

根因不是缺少更多 gate，而是 foreground owner、待执行用户工作、后台 Goal stage 和 UI identity 没有各自唯一的数据结构。

## 3. Codex 对照得到的关键原语

对照 `/Users/lordcasser/workspace/projects/codex` 后，值得借鉴的不是某个 Goal enum，而是两个底层原语：

1. `codex-rs/core/src/session/inject.rs::try_start_turn_if_idle`：所有自动 idle work 共用同一个 admission gate，并在 reservation 前后反复检查用户触发工作；
2. `codex-rs/core/src/session/mod.rs::steer_input`：附加输入进入当前 active regular turn，携带 `expected_turn_id`，拒绝 steering compact/review 等非 regular owner。

Grow 因此保留自己的 planner/verifier，但把 admission 和 steering 收敛到相同形态：一个 foreground gate、一个显式用户 FIFO、一个 expected-owner steering 命令。

## 4. 本次架构替换

### Turn

- 唯一 `ForegroundState = Idle | RegularTurn | Compaction`；
- `QueuePrompt` 与 `SteerQueuedPrompt { expected_turn_id }` 分离；
- Enter 排队，Ctrl+Enter/双 Enter/queue-row Send now 都 steer 同一 regular turn；
- 完成顺序固定为 owner settlement -> durable `TurnCompleted` -> user FIFO -> Goal idle hook；
- origin/kind/message identity 全部结构化；
- Pager 按 `messageId` 幂等对账，不按文本或到达顺序 adoption。

### Goal

- Goal 状态机从通用 BehaviorCoordinator 中独立；
- planner/verifier 是持有 `StageLease` 的后台 stage，不拥有 foreground；
- Markdown blackboard 是唯一 plan；
- continuation/finalization 是普通 internal regular turn，但不进入用户 FIFO；
- control-plane 不运行模型或排 hidden prompt；
- stage 结果必须匹配 goal/objective/plan/board/stage revisions；
- session 重载清 transient lease，由 idle hook 恢复 v5 Active Goal；Goal 与 Behavior 从同一 Timeline `control` 事件恢复，旧 architecture 不迁移，当前格式的内部冲突 fail closed 为 Paused。

### Pager/动画

- Goal Planning/Verifying 显示 chip，但不把 session 标成 Running；
- parked 只影响展示，不伪造 idle；
- `AgentActivityProjection` 同时覆盖 foreground、Active Goal、watcher、workflow、subagent 与 needs-input；
- 单个 `FrameStamp` 为所有 surface 提供统一相位，FPS 只控制采样上限；
- animation、UI state、lifecycle watchdog 和 scroll 使用独立 deadline；
- ACP 每批最多处理固定数量消息，并在每批前检查到期 deadline，持续 token 流下延迟有确定上界。
- extensions、inline media、搜索、edit 高亮与 Mermaid 等非 ACP 工作分别使用显式 frame
  demand 或 async-view completion edge；Tracing 使用独立 channel arm，不再借任一 tick
  轮询。

## 5. 删除内容

这次按架构重构处理，没有保留已 release 脏协议的兼容层。删除或替换的主要实体包括：

- Goal classifier/evaluator/strategist/独立 summarizer/stop-detector 及其模板；
- `GoalSummary`、`GoalControl`、`GoalClassifierNudge` synthetic origin；
- planner/classifier CAS latch、D1-D6 gate、零 token no-op 推断；
- Goal 专用 `GoalPlanScope`/TodoState/`plan.md` 多重真相；
- send-now cancel/promote 与 interjection fallback turn；
- Pager `skip_next_user_echo`、running adoption stash、trim 文本配对；
- 大量只固定上述实现细节的 actor/UI 测试。

最终变更规模以提交 diff 为准；历史文档不再冻结实施中途的文件数与行数。新测试固定架构不变量，而不是保留旧协议的补偿性断言。

## 6. 新测试契约

Shell 必须覆盖：

- 用户 FIFO 与 Goal idle continuation 竞争时用户优先；
- steer 校验 expected turn identity、不替换 foreground、不产生第二 terminal；
- planner/verifier 与 user turn 并行，regular cancel 不取消 stage；
- planner 失败重拉，第三次基础设施失败 pause，pause/clear 后不重拉；
- `/goal edit`、plan revision、过期 lease；
- verifier NotAchieved/Blocked/Achieved、重复 gap 阈值、finalization、预算和重载。

Pager 必须覆盖：

- optimistic echo/replay 乱序时每个 `messageId` 只有一个气泡；
- queue row 到 steer 的原子转移；
- Goal Planning/Verifying 期间仍可输入；
- 连续 ACP 流每个 bounded batch 前检查 animation deadline；
- animation 与 watchdog 同时到期互不抑制；
- foreground、Goal stage、watcher、subagent wait 和 parked 展示下的可见 frame demand。

## 7. 后续修改准则

出现新 race 时先检查它属于 foreground、FIFO、Goal stage 还是 Pager mirror。不要增加同时横跨两类 owner 的布尔 latch，也不要用文本、token 数、status 组合或 prompt-id 格式编码新的隐藏协议。若一个动作需要启动模型，它必须经过统一 turn gate 或明确的后台 `StageLease`；若只是控制状态，它必须停留在 control-plane。
