# Design

Use the existing renderer source, regexes, image validator, gateway, replay window and writer sequence. Borrowing must not cross mutable renderer access. Negative candidate checks cannot reject Markdown relative paths or bare Unix/drive/UNC paths. Preserve Markdown-first dedup and alt text; only reuse a dimension result for the same read bytes, without caching file observations. Mermaid remains conservative for entities and case variants.

Diagnostic markers are opt-in, contain source/cursor and sequence identities rather than message text, and reset with the existing replay window. A produced frame is not the physical display: correlate its writer sequence with successful acknowledgement and keep PTY visibility as an independent observation. A first frame following history application may contain later historical rows because replay scrolls forward. Background/invisible views must not claim an active history frame. No scheduling or notification ordering changes for measurement.

Build before/after with identical diagnostics and test harness, same release/default CLI settings in a dedicated target. Capture source/binary hashes, run ordinary modern 128/512/2048 and slow writer 512/2048 in AB/BA order, separate diagnostics-off and log runs. Add controlled no-draw/text candidate fixtures and correctness oracles, not a new benchmark framework. Review slash-dense text costs and all media/normalization/layout boundaries. Report overlapping stages separately and failed/ignored selections explicitly. Remove the dedicated target after verification and archive; retain small results/logs, never shared target cleanup.
