# Design

Make ensure_historical_loaded return io::Result and consume the source only on success. Full-history get/truncate/merge/max APIs propagate failure before observing or changing a partial set. Shell handle_rewind and recover_pending_rewind already return anyhow::Result, so use their existing error channel before file or transaction changes. The unused public workspace rewind_files helper must likewise return io::Result<FileRewindResponse>, propagating the initial load/truncation error instead of synthesizing success. No in-repository caller of this public helper was found. Update in-repository callers and tests to acknowledge the result explicitly; no backward-compatibility wrapper returning partial data.

Use an invalid UTF-8 temporary rewind ledger to trigger deterministic read failure, retain a live in-memory point, and prove full query/mutations fail without losing it. Rewrite the same pinned file with valid history and verify a retry sees both disk and live points. Parser handling of malformed JSON records, read budgets, synchronous blocking IO, metadata-only picker fallback and unused public rewind helpers require separate review; do not claim they are fixed by propagating IO errors.

Compiler caller audit found tasks_cancel::cancel_running_task also invokes truncate_from after committing its internal conversation rewind. Preflight the full historical load before that rewind; report failure through the rewound input's existing response instead of continuing. Handle the post-commit truncation Result explicitly as well. Cancel's previously committed turn terminal remains outside this rewind preflight; do not claim cancellation itself was rolled back.
