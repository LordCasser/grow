# 恢复长子对话的前台耗时

在同一 macOS arm64 主机用 Rust 1.93.1 的未优化构建运行三次。合成子 journal 的继承部分为 17,283,313 字节，含 1,024 组问答，每条回答为 16 KiB。写入边界之后再追加首条实时输入，模拟 worker 打开文件时 child 已接纳新任务。

| 阶段 | 三轮中位数 |
| --- | ---: |
| 同步路径处理启动通知（包含整段回放） | 1.40 s |
| 异步路径处理启动通知并建立子页面 | 0.70 ms |
| worker 运行时处理首条实时输入和回复 | 28.58 ms |
| 后台读取、校验、投影并计算文本行宽 | 1.57 s |
| 前台把旧正文插入实时消息之前 | 3.90 ms |
| 合并后首次布局（100 列、30 行） | 13.10 ms |

两条路径都从 Pager 的 ACP 启动通知入口计时。异步路径通过单独线程运行产品的历史读取和展示投影函数，同时由前台处理用户提示和回复，再用产品回执安装历史。安装完成后检查全部 2,050 行。首次布局最初在主线程计算宽度，三轮中位数为 173.34 ms。把可复用的行宽计算移入 worker 后得到表中结果。该测量覆盖事件处理和布局，不包括物理终端刷新、Shell 准入和模型响应。用下列命令复测。

```sh
RUST_MIN_STACK=16777216 cargo +1.93.1 test --locked --offline -p pager --lib measure_resumed_child_seed_foreground -- --ignored --nocapture --test-threads=1
```

## 行为验证

- 用真正的 Pager effect 派发历史任务，并占用运行时唯一的 blocking worker。父页面的非零 AgentId、打开子页面、首条实时输入、回复和终态都在释放 worker 之前生效。之后旧问答按序出现在实时尾部之前，实时行的 ID 保留，已落盘的首条输入只显示一次。
- 迟到结果无法修改替换后的子页面。父回放期间开始的恢复会等待后台结果，父绑定变更后重新取得当前归属。Minimal 在前缀到达前暂缓写入不可逆的原生滚动区。读取失败保留实时内容，重新打开可重试，成功后清除错误行。
- Shell 实际启动测试从已发布的字节边界读取子会话，覆盖完成、取消、压缩等来源以及冷恢复。截断、越界、错误身份和非法文件均有定向覆盖。
- Pager 相关回归 231 项通过，3 项手动基准默认忽略。Shell 相关回归 427 项通过，1 项并发测量默认忽略。Pager Minimal 全库 105 项通过。两个手动基准另行运行，参见[父日志并发测量](measurements.md)。

归档前全量严格校验通过 19 项。归档后全量严格校验通过 18 项，归档校验通过 995 项。
