## Why

会话 01a152cc 的失败是模型按角色提示猜测 SKILL.md 路径，随后读取已在配置中禁用的技能。现有启动扫描、SkillManager、按名称 load_skill 与 durable SkillLoad 发布已经存在；问题不是缺少扫描器。目录向模型展示绝对路径、资格过滤先于名称解析使禁用与缺失混为一谈，初始化 skills 声明失败只写日志。主说明之后的资源目前只能自己拼路径。

## What Changes

- 继续由启动 discovery 和热重载建立唯一 SkillManager 目录。模型只需名称；目录不再展示安装路径，不读取全部技能正文。
- 先确定目录身份再判断 enabled 与调用资格，禁用明确失败，不通过同名启用来源替代。系统/工具说明要求使用 load_skill，失败时报告无法加载，禁止通过 Read、Shell 或其他副本绕过。
- 同一工具增加可选 resource 参数，按技能名称读取一个包内 UTF-8 资源，支持渐进式加载。默认仍只加载 SKILL.md；不枚举全部文件、不递归引用、不执行脚本。
- Agent 初始化声明的技能不可用时明确使构建失败；初始化技能仍在运行时目录内，可继续读取资源。普通文件审阅不伪装成 Skill Loaded。

# Impact

涉及 tools 的目录/工具、agent 初始化、Shell 权限预检、Timeline 调用参数一致性校验及测试。复用现有 SkillLoadItem/ACK/保护正文/冷恢复，无新增数据库、后台索引任务或工具。MCP 运行时不改动。通用文件工具仍可用于用户要求的技能编辑与审阅；禁用策略不是新增的 OS 文件沙箱。
