# Design

The asynchronous compaction worker is the owner of its Sideband attempt and Goal usage receipt. Ordinary authority invalidation can occur while the root Session is applying the exact Goal event that caused it. If that invalidation joins the worker, the worker's settlement receipt waits in the same root inbox while the inbox handler waits for the join. Ordinary cancellation therefore signals the existing token and retains unfinished ownership in the existing slot; it may reap a worker only when the handle is already finished. The existing root command dispatcher handles usage and settlement receipts both during normal operation and while shutdown drains are in progress.

Explicit suspension and teardown barriers signal and join the same worker before publishing the cancellation terminal. Their command pump remains able to dispatch the Goal settlement commands that the worker needs. The graceful and fatal shutdown pump also drains child Sessions through the same loop. A synchronous owner guard returns the original handle to the existing slot if a barrier future is dropped while joining. Runtime suspension passes its existing shared deadline through the drain: timeout is an error and must not be reported as a completed freeze. No new task, store, or actor is introduced. A cancelled or late generated summary continues to bypass Surface commit.

The established deadlock path is `RecordGoalUsageIncomplete` → `apply_captured_goal_usage_incomplete_outcome` → cancellation while a promoted `finish_background_compaction` owns the worker; generation owns the Sideband attempt and submits `SettleGoalUsageAttempt` to the same root inbox. The focused regression is `async_compaction_promoted_job_with_incomplete_usage_cannot_commit`, which now routes both commands through one serial dispatcher.
