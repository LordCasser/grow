# 2.4.3 → 2.5.0：官方 release 端到端 resume 对比

同一台 Apple M4 Pro（12 核、24 GiB、macOS 27.0.1），直接执行两个版本的官方 macOS ARM64 release-dist 二进制。不是 debug / 普通 release 的跨构建比较，也不是将各项局部 A/B 相加。每轮约32 KiB assistant 正文，512/2048/4096轮分别约16/64/128 MiB；默认诊断关闭，50×120 PTY，新进程、独立 HOME/GROW_HOME、本地 mock，文件页缓存因刚生成夹具而温热。

## 最终结果

从调用 `grow --continue` 的 PTY spawn 前起算，单位秒，**中位数 [min, max]，每格 n=5**。首历史指首个含历史正文的完整可观测帧，未要求一定显示第一轮；末屏指最终唯一 sequence marker 所在完整帧。可输入不是从最后正文或模型标签推断：末屏且 Loading 消失后发送不提交的草稿探针，观察其在完整帧回显，因而是外部可观测输入就绪的上界，含按键/回显传输成本。

4096轮可输入耗时约为原来的1/8.43，减少约7.38秒；2048轮约为原来的1/5.51，减少约2.66秒；512轮约为原来的1/3.23，减少约0.47秒。更长样本中整体收益确实更大，但不能将这个趋势无限外推。百分比基于未舍入的中位数。完整最终聚合与二进制身份见 [results.json](results.json)。不是 p95 或跨设备保证。

512轮新版的首历史与末屏均在同一完整帧被观察到，不能据此声称没有交付前历史或制造额外滚动。2048轮新版末屏有约0.17秒的观测范围，受既有绘制边界和调度影响；未改帧节奏或插入播放延迟。可输入相对首屏的改善更大，不能拿首屏代替完整 resume。

## 样本与版本有效性

- 2.4.3 为 `grow 2.4.3 (2069c43)`，完整 source `2069c43db5a3756bf65d1a275e8ed16bef3a86fa`；2.5.0 为 `grow 2.5.0 (8443a4d)`，完整 source `8443a4d1648d17b10f993c845cb68d949c55235e`。下载 checksum/API digest/size、build-one.yml attestation 的完整 source digest、codesign 和隔离环境版本均核对通过；archive 与 executable SHA 见结果 JSON。两者沿用官方固定1.93.1工具链与 release-dist 构建流程。
- 使用既有现代 admission synth：每轮 user + 32 KiB assistant、稳定递增 marker、合法 Request/Admission/Turn，以及同样配置的 catalog、rewind 和模型路由。旧版使用现有 test-only exporter 转为它支持的 Timeline+updates/summary v6；新版为统一 journal/summary v7。没有把旧格式塞给新版、忽略 schema 错误、跳过校验或新增产品兼容路径。
- 同一规模所有版本/轮次的逻辑角色、正文顺序及字节 BLAKE3 一致：512轮1024条/16,797,586正文bytes；2048轮4096条/67,191,722正文bytes；4096轮8192条/134,384,554正文bytes。真实两份 CLI 在每组排除的预热中经 stdio session/load 再完整交付一次，逐角色/正文/顺序的摘要与计数必须完全一致。旧格式可读性不是只看末条 marker 的推测。
- 6次预热排除，正式每规模五对按BA/AB/BA/AB/BA交替，新建隔离会话和子进程；夹具生成、摘要、wire oracle不在计时内。所有恢复和不提交探针均未触发推理，Ctrl+D退出码均为0。闭合 `CSI ?2026 h/l` 帧后再取屏幕，避免将局部接收字节当作已完成的输出帧。

## 对抗性审查与限制

已有局部基准不能串成整版收益，所以此次只比较实际官方版本。新旧物理字节量不同是存储组织本身的结果，不为追求相同文件大小添加无意义数据；等价性以同样逻辑消息、因果夹具和真实 wire 正文/顺序为准。

本任务自有编译/Clippy全部结束后才计时。其他任务持续触发编译：初始短矩阵两轮因污染整体排除，最终512/2048矩阵先等待60秒无编译，再以0.5秒间隔监测，全矩阵0次命中。扩展4096/6144的前两轮完整矩阵也全部因编译污染排除，没有从中回收快样本。

随后在新采样前固定pair级排除协议：首对前等待10秒安静窗口，pair0只做排除的预热与完整wire校验；pair1..5保持既定BA/AB顺序，任何编译命中都整对重测同一pair，不按耗时筛选。4096轮pair2前两次排除，第三次通过，最终五对正式样本各0次命中；预热的编译命中不作性能样本。源文件和executable SHA前后均一致。两组observer仅驱动配置不同，观测/夹具/oracle完全相同，独立只读diff已核对。

6144轮（约192 MiB assistant正文）也完成过正确性校验，但pair级采样持续受干扰，仅取得两对有效正式样本、另排除十对尝试。为避免无边界重试，在完成当前pair且无存活子进程的边界停止；未达到五对，因此所有6144计时均不进入表格或notes，不报告其收益。完整采样/排除计数见results.json，不将失败环境伪装成加载失败。

编译监测不能排除短于0.5秒的活动；机器也非独占，其他应用与热状态仍是限制。观察器包含PTY接收/模拟终端与同步帧观测成本，结果不是物理显示器扫描或裸RPC耗时。

本次是根会话纯文本合成负载，不代表图片、Mermaid、密集工具、子会话树或冷盘的同幅收益；没有新增这些负载的整版性能结论。现有完整校验、历史顺序和就绪屏障由实际发行程序保留；未做就绪与历史分页分离。按键探针仅验证可编辑输入，不把它描述为一次付费模型请求的首 token 时间。n=5 是本机证据，不是统计分位数或性能承诺。

独立只读数值复核从各规模最终有效样本重算，确认两组共36行=6预热+30正式，每规模/版本各5正式；三个主指标的中位数、范围、降幅和输入倍数均与聚合一致，消息摘要一致、推理请求0、正式样本所在窗口的编译监测为0命中。原始cast/日志/临时采集脚本仅用于本轮核对，按仓库约定在收尾删除，不收入归档。
