# Design

`agent::prompt::agents_md::read_agents_config_with_roots` owns the ordered rule roots and candidate attribution. Resolve cwd with the existing dunce canonicalization before `discover_worktree_root`, then walk physical parents to that same returned root, inclusive. This repairs both the stop test and missing physical ancestors; canonicalizing equality alone cannot repair an alias whose lexical parent chain never contains the checkout. Project candidate file_path values use the physical chain, so displayed source paths describe the actual checkout. Preserve current candidate canonical dedup and filename ordering, home rules first, and explicit workspace user root insertion/dedup after the checkout root. Keep no-repository behavior to one cwd. If canonicalization fails, do not ascend lexical parents as if a physical checkout had been established; the existing no-repository single-cwd fallback may probe only that supplied path.

Do not replace the other `RepoDirChain` walker as part of this change: it has separate callers and a home-is-dotfiles policy. This rule function currently calls `discover_worktree_root` directly and has no home filter; retain that policy, including when the returned checkout happens to be the home directory. Confirm it with an isolated child environment if testing the actual home case; do not mutate the parent's HOME or user checkout. No new public API, discovery framework, cache or dependency is necessary. Caller-supplied cwd stays unchanged for session/tool execution; only rule source discovery uses physical identity.

Verification calls the actual production rule discovery and parser with synthetic user roots: normal nested checkout and external alias-to-root / alias-to-internal-subdir must produce the same ordered checkout root→nested content, with no outside AGENTS or .grow/rules; explicitly configured workspace user roots still participate exactly once. Linked worktree alias must stop at the actual worktree root rather than the main checkout or external alias parent. Outside Git only cwd contributes. Retain existing home/project dedup controls and separately verify existing home-as-repo behavior in an isolated child if needed. Parent reviews results and runs the Agent prompt/rules suite, preserving AC-05 namespace cycle semantics in the same crate.
