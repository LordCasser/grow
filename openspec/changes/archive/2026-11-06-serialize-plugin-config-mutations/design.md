# Design

Shell configuration is the owner of raw config.toml transactions. Its existing `lock_config_writes`, `read_to_string_or_empty` and `atomic_write_string` provide the required process-wide serialization, hard-read handling and atomic replacement with retained permissions. Keep the existing Tokio mutex; replacing it with a blocking mutex across settings' async I/O or calling blocking_lock from a runtime can deadlock or panic. Plugin mutations become async and acquire that same lock before reading, retaining it through TOML mutation and publication. Use raw `toml::Value`, not effective Config, so unknown keys and authored environment references survive. Invalid TOML and hard read errors must return before any publication. Existing add/remove missing-file and idempotence semantics remain; no new cross-process or fsync guarantee is claimed.

The shared Shell interface is fixed: `add_plugin_path`, `remove_plugin_path`, `add_disabled_plugin`, `remove_disabled_plugin`, `add_enabled_plugin`, `remove_enabled_plugin`, `add_dismissed_plugin_cta` each become `pub async fn(&str) -> anyhow::Result<()>`; existing `add_dismissed_plugin_cta_to_file(&str, &Path)` likewise becomes async with anyhow::Result. `post_install_plugin(&str)` becomes async returning the same `(Vec<String>, Vec<String>)`. No blocking sync compatibility wrapper is retained. Helpers may be private and path-parameterized for tests; do not add a public generic configuration framework. Hook paths use a different file/owner and are untouched.

Shell actor/slash/marketplace callers await these functions. `shell::plugin::install_plugin` and `install_marketplace_plugin` become async and retain their existing result types; the marketplace private post-install callback may use Rust's existing AsyncFn support so only the real post-install action and its test seam become async. Keep registry save/removal warning policies unchanged in this change. Toggle operations continue composing their existing individual raw edits; this work guarantees each edit's read-modify-publish transaction, not a new multi-operation rollback protocol. Installer errors and plugin update adoption remain AC-08/AC-07.

Pager's CLI entry already runs async: install/enable/disable handlers and direct callers await the fixed Shell APIs, with necessary internal propagation. For CTA dismissal, mouse handling retains its current immediate local hide/dismiss/diagnostic behavior but queues a `PersistDismissedPluginCta { plugin_id: String }` Effect. The existing effect executor awaits the Shell write, logs the existing persistence warning on failure and returns the existing no-op completion; no new runtime, thread, Action, durable queue or acknowledgement UI is needed. This is a concrete UI→persistence boundary requiring one Effect variant. The path-parameterized CTA test awaits the same write.

Implementation increments are separately owned: Shell transaction behavior plus its Shell adapters/tests; Pager async consumer/effect adapter plus its tests. They may prepare independently against the above interfaces, but compilation acceptance waits until both are integrated. Parent verifies the full actor/CLI/mouse→transaction path.

Verification must demonstrate hard-read/parse/write failures preserve original bytes and unrelated raw keys/environment references, successful atomic replacement retains Unix modes, and plugin/CTA edits share the settings lock under a controlled concurrent update. Prefer existing path helpers or isolated child HOME/GROW_HOME over global environment mutation; do not touch real user config. Include actual plugin action or CTA adapter evidence, beyond a new helper test, and retain the settings persistence suite. Platform-specific permission checks are gated honestly. No tests may relax fault expectations merely to get green.
