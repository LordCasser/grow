# Design

`write_tree` already writes each `transcript.md` with `create_new`, applies private Unix permissions, and calls `sync_all` on the file before success. The final recursive pass exists to sync directory entries before the caller publishes the prepared tree or archives it.

Use a small platform-specific directory-sync helper, matching `pager/src/local_drafts.rs::sync_dir`: Unix opens and syncs directories and returns any error; non-Unix platforms return success without attempting the unsupported directory open. This is an explicit capability boundary, not an error fallback. Sync the completed temporary tree before publication and sync the target parent after the no-replace rename. A parent-sync failure is reported even though the complete tree is already published; do not try to remove a possibly visible target. File writes and file `sync_all` remain unconditional and fallible on every platform; no unknown I/O error is swallowed.

The trajectory handler keeps ownership of its temporary archive in the streamed response body so cleanup runs when the body reaches EOF or is dropped after client abandonment. Regression coverage should exercise the production `write_tree` and `archive_tree` path with a verified parent/child fixture whose canonical session ID contains multibyte characters, then extract the gzip tar and compare both documents. The HTTP test should consume and unpack a valid archive response, and separately abandon a response before EOF and verify its temporary archive is released; this checks delivered bytes and both cleanup paths rather than comparing a mocked byte string.
