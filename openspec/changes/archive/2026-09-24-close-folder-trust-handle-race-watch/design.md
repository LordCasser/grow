# Decision

Folder Trust is a user-intent gate for repository-supplied config and commands, not an OS sandbox against a concurrent local principal with access to the workspace's parent pathname. The current identity key binds canonical checkout root, `.git` marker and common-dir entities, and the store/cache revalidate that identity at the decision boundary. It prevents an already-replaced checkout from inheriting a prior grant.

There is still a real check-to-use race. `find_project_configs` returns paths, `resolve_effective_plugins_config` opens those paths after a trust verdict, `.envrc` is sourced from a path, and hook/MCP/LSP commands choose cwd by path. On POSIX, a different principal with write access to the containing directory can rename a trusted checkout without write access inside it. That distinct shared-parent case is not eliminated by the present checks. Same-OS-user concurrent replacement is not a meaningful extra protection target: that principal can also modify the user's trust store or already-trusted project files directly.

Closing the race fully would require one held directory capability through all project discovery and reads plus executable/cwd binding for every spawn. Rechecking a pathname before launch merely moves the race. Windows `CreateProcess` accepts a current-directory string rather than a directory handle, so a portable implementation is not a small local refactor. The project has no demonstrated incident or stated guarantee against a hostile co-tenant controlling a shared workspace parent. The broad change would therefore impose substantial cross-platform complexity for a threat model Folder Trust does not promise to solve.

Retain the limitation in developer architecture notes, without implying the race is fixed. Reopen only if multi-principal shared-parent workspaces become an explicit supported security boundary or a concrete exploit/incident establishes that requirement. Then design a platform-specific capability or isolation model, including the three check→open, open→parse and parse→spawn windows, as its own change.
