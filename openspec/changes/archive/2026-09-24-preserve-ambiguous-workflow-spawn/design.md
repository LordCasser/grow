# Design

The Timeline `Spawned` fact remains the only admission authority. ChatState validates the event before calling its persistence port. Its `Invalid` response therefore proves no Spawned append was attempted; a projection failure after a durable append gets a distinct error. `Persistence`, `Cancelled`, `AcknowledgementLost`, and post-commit projection failure can all follow an attempted append; in particular a retry can observe a permanent error after an earlier acknowledgment was lost. For those errors the manager must not write `cleared` or drop the immutable script/args source. It returns an error containing the run identity and an instruction to inspect the session after reconnect. If the fact was durable, normal cold recovery closes an open execution as interrupted and restores it from the seed and source files. If it was not durable, restore ignores the orphan source directory because it enumerates only Spawned facts.

No new Timeline event is needed: the current API has no post-admission forget operation. Adding `Forgotten` after an uncertain Spawned would not close the crash gap between the two appends. A future committed-run forget feature would need a separate contract and durable operation.

Test the ambiguous boundary with ChatState's manual persistence acknowledgment. Deliver the Spawned append to the fake writer, acknowledge it, then cancel the actor before it can acknowledge the caller. Assert the manager leaves the source and tracker intact and that the recorded Spawned fact replays as a recoverable lifecycle. Existing oversized-manifest coverage protects the proven pre-append rollback.
