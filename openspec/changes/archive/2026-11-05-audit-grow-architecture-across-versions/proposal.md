## Why

用户要求按当前 software-engineering skill 清查整个 Grow 代码仓及各版本的架构实现，范围超出模型切换特性。需要以代码、调用方、历史版本和验证证据区分现存缺陷、已修复问题与独立债务，避免把局部通过当作全仓结论。

## What Changes

- 枚举全部 workspace crate、非 workspace/vendor、脚本和构建发布入口，并审视职责、依赖方向、状态所有权、公开契约、资源生命周期、错误传播、复杂度依据和验证缺口。
- 枚举本地 Git 的所有 46 个发布标签（v1.0.0 至 v2.6.0）及当前工作树；逐版本核对相关模块结构和变化，按相同代码树复用结论时明确 tree/diff 依据，不把当前代码结论追溯到未经检查的版本。
- 各分区报告可定位发现、触发/后果、历史演进与当前状态，并形成全仓覆盖矩阵和总报告。
- 无关债务登记既有 backlog；行为修复另建 change，不在纯审计中悄悄实施。

## Capabilities

### New Capabilities

无。本 change 只产出审计记录，不改变执行行为，`.openspec.yaml` 设置 `skip_specs: true`。

### Modified Capabilities

无。规范和代码偏差作为发现记录，不为纯审计虚构 delta。

## Impact

产物限于本 change 下的 inventory、分区审计、总报告、验证记录，以及必要 backlog 引用。审查基线为 HEAD `d6128138c`、用户开始时未提交改动和同轮新特性最终版本；活动实现区域在其完成后复核。Git 历史完整（非 shallow），版本范围覆盖所有本地发布标签；外部未取回提交不冒充已审。审计强度是基于全模块/全标签结构清单的代码审查与针对性验证，不承诺逐行穷举所有历史提交或在所有平台重编每个旧版本。
