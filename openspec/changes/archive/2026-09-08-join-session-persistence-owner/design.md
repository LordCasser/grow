# Design
Use the existing SessionThread lifecycle ownership boundary to track both the dedicated actor thread and the separately scheduled persistence task. Prefer a passive completion signal which does not retain a PersistenceMsg sender or StorageAdapter: completion must be published only after the task releases its storage, including panic/cancellation. A cloneable completion observation can be captured before moving PersistenceHandle into the actor thread. Avoid another session registry or global poller.

Existing drain polling must remain asynchronous, so the originating Tokio runtime can actually finish its persistence task; blocking that runtime while waiting for its task would deadlock. Preserve timeout/error behavior and retain the incarnation on a timeout. Cover normal close, idle unload/replacement, failed actor initialization and panics; inspect all SessionThread consumers before implementation. Noop/test-only persistence handles must have an explicit already-finished observation rather than hang.

A flush acknowledgement is not an exit acknowledgement. Do not close persistence prematurely while teardown producers still own append rights. Preserve existing final flush and receiver drain. Do not change storage corruption handling or effort hydration. Same-session detached append producers that retain senders beyond session-thread exit require inspection; do not disguise them with a timer.

The first integration run with passive completion alone timed out at close: a coordination backend retains a SessionHandle, and workspace resource unbinding follows lifecycle drain. Therefore completion cannot depend on all external senders disappearing. After the dedicated thread exits, request receiver closure through a weak persistence sender; the receiver drains all accepted messages then exits. No stop is requested while the actor thread is still live. This is an explicit terminal mailbox boundary, not a forced task abort.
