# 设计

## 活动分组

把可连续聚合的工具调用和 Thought 视为同一活动序列。组边界取自对话切换、显式 Skill 行或独立交互；工具调用与 Thought 之间的交替、工具类型变化、运行/终态更新和成员展开都不构成边界。纯 Thought 序列仍按 Thought 展示，不创建没有工具成员的工具组。单次工具调用可保留现有动作式呈现。

分组保持来源顺序，不把完成顺序或当前运行状态当作重排依据。Skill 仍独占一行，并在其前后隔开活动组。摘要从整组成员计算，而非当前可见前缀；工具调用数来自工具成员，Thought 不增加工具计数。失败成员仍属于原组且可以检查，工具类型只取实际结构化身份。

## 折叠和展开

折叠组隐藏已完成 Thought，但保留活跃 Thought 与工具预览、用户手动打开的成员、待用户响应内容和 Hook 信息。展开组按输入时序呈现所有成员，并允许打开单项正文。组折叠、成员正文展开和交互待响应是不同可见状态；更新其中一项不隐式重置另外两项。

继续使用现有 `GroupSpan`、`EntryId` 与 `expanded_groups` 所承载的分组和展开状态。此次行为不要求新增持久化状态或通用分组框架。实现时需要确认稳定成员身份如何贯穿 live 更新与 replay；状态更新只修订同一成员，不因状态或类型细化生成新组。

## Live、replay 与布局

live 与 replay 对相同事件序列产生一致的分组、身份、顺序和摘要。追加、完成、工具类型细化及布局 resize 均保留当前组与成员的手动展开选择；布局只影响换行和空间分配，不改变分组。聚合完成后统一应用 dense truncation，不能让其把活动组按成员重新截断。

`show_thinking_blocks` 继续决定 Thought 是否显示，不因纳入活动分组而改变其隐藏/显示语义。组折叠规则只作用于应显示的 Thought；启用思考块时展开组可查看完整原文。

## 边界

修改限制在 client surfaces 的活动行投影与交互行为。工具/Thought 的来源事实、工具执行生命周期、Skill 独立行、对话语义和存储格式均不改变。实现不得用展示文本猜测工具类型、把失败过滤掉，或为连续分组引入新的持久化协议、配置开关和无关重构。

## 布局投影

活动范围包含前置和尾随 Thought，并使用该范围首条原始记录的稳定 EntryId。成员运行状态、显示模式和待响应/Hook 状态仅决定是否在折叠组中保留原生内容。单独工具保持单项动作，工具与 Thought 的混合活动可形成摘要；纯 Thought 不创建工具摘要。

布局保留成员原生高度 unfolded_height，重复投影先恢复该高度，再写入折叠后的 height。组首槽可容纳一行合成摘要及原生正文的完整高度，因此首成员运行预览或手动展开不会丢失正文。键盘打开折叠组、鼠标点击摘要行和点击成员正文分别沿现有交互入口处理；普通流更新不迁移组锚点。
