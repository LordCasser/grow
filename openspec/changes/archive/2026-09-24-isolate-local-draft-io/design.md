# Design

Retain local-draft policy and file format in `LocalDraftRuntime`/`LocalDraftStore`. A single worker owns a runtime and executes its existing synchronous store operations away from the UI thread. Pager captures the bounded per-agent draft record and binding on the UI thread. At most one ordinary snapshot is queued or executing; later edits replace the coordinator's latest snapshot and are sent when the worker acknowledges the first. A close, reopen, or session-key transition turns any unsent preceding snapshot into an ordered boundary command before the new binding, so its last edit cannot be coalesced away. Ownership-transfer invalidations drop the old unsent snapshot and enter the same FIFO before any post-RPC edit. The final checkpoint includes any unsent snapshot and waits for the ordered worker result.

The worker sends recovered-record proposals with the snapshot generation and binding. Pager compares them with current agent/session/cwd, current capture, content epoch, and ownership epoch before mutating the composer. A response based on a stale edit is ignored; the next snapshot carries the newer live draft. The worker retains an unacknowledged load proposal when a quit checkpoint races the UI result, so an unchanged empty composer cannot delete a saved record before recovery is applied. The worker owns retry timers for failed writes/removals and never leaves an expired retry as an always-ready UI timer. The checkpoint sends the latest snapshot after older commands, attempts all due or dirty writes and removals immediately, and acknowledges only after worker I/O returns; a stopped worker makes normal quit fail.

Use a controlled blocking test store operation to show that the UI-facing synchronization returns while the I/O is held, and test load-versus-edit, invalidation ordering, retry, and quit. Preserve the existing direct-runtime tests for file format/quarantine behavior; add focused worker tests for concurrency semantics.
