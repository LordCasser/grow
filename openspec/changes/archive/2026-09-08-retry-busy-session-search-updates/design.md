# Design
Preserve rusqlite::Error as the io::Error source, then downcast and match DatabaseBusy/DatabaseLocked explicitly. This avoids treating an unrelated filesystem WouldBlock as SQLite contention. All sqlite_to_io_error consumers are local index/metadata wrappers; no public structured error contract depends on its former formatted-string payload. Reuse pending deadlines for delayed retry, rather than creating another queue or persistence schema. A fixed nonzero contention retry interval is sufficient initially: retries are frequency-bounded and continue while that worker is alive. A new notification can coalesce by the existing session key. Success removes the pending item; non-contention errors retain existing failure logging and are not retried indefinitely.

Verify the real lock path with an explicit temporary SQLite index and a held write lock, using a missing session so the operation is an eviction. First attempt must leave a retry pending and the old row present; after lock release, the same pending work must remove the row without another notification. Verify successful work is removed, permanent errors do not spin, and absent-index eviction still creates no DB. Do not run against user history or make permanent error classification depend on English substring matching.

This is an in-process recovery contract. Runtime/process exit can still drop pending projection work; existing bootstrap/rebuild remains responsible for cross-process repair. Bootstrap lease policy, fairness across many keys, worker shutdown draining, cache schema migration and indexing-disabled upserts are separate concerns.
