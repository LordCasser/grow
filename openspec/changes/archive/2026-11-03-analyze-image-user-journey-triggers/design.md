## 分析方法

从用户动作、ACP/模型工具或自动触发点追到 command 接纳、actor gate、冻结/投影、HTTP 与终态，不从 helper 存在推断入口可达。Atlas scoped 查询只作局部结构证据；run loop 的 match 分派及动态 UI 链用源码核对。

穷举以当前生产代码的分支条件为边界：图片分为无图、已有描述、转换待 ACK、未描述、混合、已移除；路由分为已确认纯文本与未标记（实际视觉模型与未知模型在代码中共用这一分支）；来源分为当前冻结与压缩前旧 snapshot；生命周期分为允许、取消/接收端关闭、暂停/关闭。UI 门禁与最终写入条件另列，避免把模型请求成功等同于旅程成功。

不机械展开所有笛卡尔积：同一入口、同一分支、同一终态的组合合并。矩阵列出全部入口和会改变控制流的状态类别。实际执行的测试、源码结论、当前契约限制和未执行的 UI/真实进程验证分别标识。
