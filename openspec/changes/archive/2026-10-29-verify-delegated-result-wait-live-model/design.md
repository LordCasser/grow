## 场景

使用截图中的 `opencode/deepseek-v4.1-flash`、max effort 和当前 Grow。主 agent 先派发一个真实后台子 agent 取得远端报告，同时自己读取本地 CSV 并写统计结果，最后合并两份结果。测试提示不提 `get_task_output`、sleep、等待工具、timeout 或原 ID；不通过工具过滤排除错误选择。

子任务运行一段本地 fixture，等候由测试驱动提供的报告输入。驱动仅控制输入到达时刻，保证主 agent 完成独立工作时子任务仍未完成；模型回答和工具选择全部来自真实 provider，不使用 mock 模型或预编排工具调用。驱动观察到主 agent 对原 child 的正超时输出等待后交付数据；如出现 sleep 占位或提前结束则保留失败证据，不将其改判成功。

## 判据

必须实际观察到后台派发成功、主 agent 在其后完成本地统计、原 child 尚未完成时主 agent 对同一 child ID 发起正超时等待、结果交付后主 agent 合并正确。整个主 agent 工具轨迹中不能另派空等待任务或调用 sleep/等价计时占位。保留原工具名、参数、身份与顺序证据。

Headless 使用 `--no-wait-for-background`，排除 CLI 自动等后台结束造成的假阳性。保留 shell/task 可用性，设置有限的模型回合和单次实验期限；触限、网络失败或证据不足均不判成功，不自动重跑直到通过。

## 边界

一次通过只能证明该模型在该次场景中选择正确，不能推出所有模型或所有任务的遵循率。只归档最终核对后的脱敏证据，不归档凭据、完整 provider 配置、原始思考或临时日志。
