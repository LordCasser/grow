# Verification

- `ListPaneState::prepare_layout` derives `effective_width` from the viewport width and whether a scrollbar is known to be needed. It recomputes `height_cache` whenever `height_cache_width != effective_width` or items shrink, and records the width after recomputation. `LayoutStamp.width` uses that same effective width; a width or wrap-mode difference forces the layout cache to rebuild. The phase-2 scrollbar correction recomputes all physical heights, updates `height_cache_width`, rebuilds `ListLayoutCache`, and stores the corrected width in the stamp.
- Resize is observed on each owner render because owners call `prepare_layout` with the current content width. If the viewport height changes which side of the scrollbar threshold the list occupies, the resulting effective width changes and takes the same recompute path. If only viewport height changes while effective width stays the same, item geometry is width-dependent only and remains valid.
- The variable-height production owners are `BlockViewerPane` and file-search `LineViewerState`. Block viewer streaming ticks rebuild items on generation changes; background-task output changes rebuild and invalidate; raw/data/theme and communication-width rebuild paths call `invalidate_layout`. Line viewer calls `rebuild_markdown_for_width` before every `prepare_layout`; a width change also changes ListPane's effective width and rebuilds the height cache. `rebuild_with_comments` explicitly invalidates after replacing rows. Queue, todo, task, and subagent-catalog list owners use `WrapMode::NoWrap`, so their row geometry is fixed-height.
- Existing regressions: `prepare_layout_full_rebuild_on_width_change` covers state resize; `scrollbar_width_fix_verified`, `scrollbar_fix_phase1_many_items`, and `scrollbar_fix_phase2_few_heavy_items` cover effective-width changes for actual wrapping content. No source mutation or resize path was found that can leave a production variable-height cache keyed to a stale width.
- No runtime behavior changes; no Cargo build or tests were needed for this source audit.
