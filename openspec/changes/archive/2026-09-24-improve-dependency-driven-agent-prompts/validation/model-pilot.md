# Bounded real-model pilot — 2026-09-24

This is an exploratory check of model behavior, not proof of a general speed or scheduling improvement. The archived contract requires **model-visible guidance**, not deterministic model obedience. The fixture sources and compact, ordered tool traces are in [model-pilot/fixtures](model-pilot/fixtures) and [model-pilot/runs.json](model-pilot/runs.json). The JSON includes exact user inputs, binary and fixture SHA-256 values, tool inputs (file-write bodies represented by hashes), the final answer tail, elapsed time, and provider-reported usage. No provider credential or full local configuration is stored here.

Both binaries were built from `b0a835cc` with `cargo build -p cli --bin grow --locked` and separate `CARGO_TARGET_DIR` directories. The baseline source changed only the primary/subagent audience bodies, general-purpose/explore role bodies, and two task-tool descriptions back to their pre-change text. It retained the current subagent capability authority and unrelated runtime contracts. Binary SHA-256: baseline `305c6b9e87c7d887e643217ba5da34722292a5510ac9762939e8f2e4521ae541`; candidate `001160567088c2e15f76cde645149d1b6a9ea695824b3d0e52a0b053dfbe0200`. Embedded unique audience text was checked in each binary.

Every paired run used `deepseek/deepseek-v4-flash`, `--reasoning-effort max`, `--permission-mode auto`, `--no-memory`, `--max-turns 30`, the same built-in tools and exact prompt, a fresh copy of the same fixture, and an isolated `GROW_HOME` containing only the provider configuration. No external MCP server or test service was configured. Runs were sequential, not concurrent. Wall time includes provider and local tool latency. One sample per side cannot establish statistical significance; provider load and stochastic output remain uncontrolled. `total_tokens` is the reported sum of uncached input, cache-read input, and output; for E11 the parent end event includes its settled child. It is not a price estimate.

For E01 and E02, the independent Python tests returned exit 0 in both output workspaces. For E11, byte comparisons of every fixture file returned no modifications in either workspace. These checks are separate from the model's statements. The E01 shell commands piped test output through `tail`, so their process exit code alone did not prove the initial failure; the trace shows the failure text and the independent post-run test verifies the fix.

The original E01–E15 matrix remains in [validation-plan.md](../validation-plan.md) as diagnostic hypotheses. E03–E10 and E12–E15 were not run. E02 did not reach its intended parallel condition. The pilot does not validate wait-all timing, premise invalidation, message receipt versus handoff, Sideband blocking, or Plan/Full behavior in a live interleaving. Their **guidance text and composition** are covered by deterministic tests and source review in [verification.md](../verification.md); actual model adherence is not inferred from those tests.

Completing the original recommended three pairs for each of 15 scenarios would require at least 90 model runs and a driver that reliably controls child completion, interrupt delivery, and changed premises. These artificial interleavings would mostly measure one provider's stochastic decisions rather than the stated contract that Grow emits specific guidance. The three paired pilots exposed cost and a possible bounded-explore benefit without any basis for an overall efficiency claim. We therefore stop the model experiment here and accept the prompt contract on deterministic delivery/composition and semantic review. If a concrete scheduling failure appears later, reproduce that failure with a focused scenario rather than carrying an open, unbounded evaluation task.
