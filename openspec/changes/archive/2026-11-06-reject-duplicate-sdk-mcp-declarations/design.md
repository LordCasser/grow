# Design

Shell `session::acp_mcp::parse_acp_mcp_servers` owns decoding of one SDK metadata array, while ACP new/load own admission before session state changes. Change the existing function to `Result<Vec<mcp::servers::AcpServerEntry>, String>`; absent metadata returns Ok(empty), malformed entries retain the existing warning-and-skip policy, and duplicate successfully parsed `name` values return a clear duplicate-name error. Use the canonical existing McpServerName identity (currently exact name equality); do not invent normalization, case folding or serverId-based identity.

Call this parser at the beginning of both new_session and load_session next to existing standard-array name validation, before trust/discovery/persistence/lifecycle retirement. Keep validation at the start of spawn_and_register_session too, capturing the parsed Vec before its first preparation side effect and reusing it at spawn; the builder can also be called internally. The outer request guard and inner builder guard protect distinct entry boundaries using the same pure parser, not independent policy copies. No new public schema, source registry or SessionSpawnOptions field is required. A resident load with invalid recognized SDK declarations is rejected without replacing the resident handle/catalog. Do not expand update_mcp_servers, whose present schema only accepts standard servers; its existing duplicate validation remains.

Source precedence across standard/config/plugin/SDK inputs is unchanged. The archived contract rejects duplicates within one client array, not arbitrary same names across distinct configured sources. This change does not implement MCP-F1 post-initialization call admission or MCP-F2 registration connection routing.

Tier 3 exercises real ACP trait new/load with duplicate SDK metadata and checks invalid_params with duplicate reason before session publication, old-handle retirement, storage writes, or commands. Include a retained resident fake handle/catalog and ensure it stays unchanged on load failure. Parser positive controls preserve valid entries, absent metadata and current malformed-entry policy; duplicate standard array tests remain green. Parent reviews actual early-guard order, owner state and tests; coder exports a narrow isolated delta and awaits serialized Cargo grant.
