# Design

Use existing scan_opened_sessions projection to retain Summary values, completing duplicate-ID checks before mutation. The discovery summary selects candidates but does not authorize deletion. For each initially expired, non-skipped candidate, create an operation-scoped adapter sharing the already pinned root authority and directory mode but with empty directory, writer-lease and Timeline-prefix caches. Open the candidate through existing identity validation, then recheck its current summary and TTL under the existing writer lease before deleting the same pinned entity. Drop that operation adapter on every outcome. This reuses the adapter's resource ownership rather than adding a lease-guard framework or evicting a live writer's cache. A writer owned by the caller also remains a conflicting writer.

Identity is pinned at candidate admission, after discovery; do not compare an inode-only token after releasing a handle or treat the original summary as permission to delete a replacement. Current summary age, hidden status and identity determine eligibility. Initial discovery remains before all deletion, preserving the no-deletion-on-duplicate-scan-error boundary. Per-candidate reopen errors are counted and reported; no callback on preserved or failed candidates. Explicit-directory mode continues to return no candidates.

Tests must use temporary roots and reduce descriptors only inside an isolated child process. Cover histories larger than the soft descriptor limit, held writers, refreshed/invalid summaries, skip path, and duplicate discovery failure before deletion. Keep unrelated scanner error-classification policy out of scope.
