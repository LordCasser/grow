# Design

Split renderer source finalization (flush pending normalizer bytes) from full final render. Existing renderer.finish remains eager and equivalent. MarkdownContent records whether chunks arrived through the existing deferred path and whether its final derived cache remains pending. Live and one-shot rendering keep their existing eager path.

At deferred finish: finish source immediately, invalidate wrap tracking and generation, and mark final presentation pending. Every derived-view getter materializes a complete final render before returning; text/is_empty stay source-only. Wrapping sets current theme/table width before final materialization. A later chunk first resolves any previous pending finished view before resuming the existing streaming behavior, preserving append-after-finish and hyperlink/frozen-prefix semantics. Clones retain correct state; no separate clone/cache framework.

Agent finish retains image-prefix handling, image file reads/validation/dimensions at the same boundary. Mermaid detection remains at finish when the completed source might contain Mermaid (case insensitive, or a character reference could encode the fence info); other sources can return an empty diagram skeleton without forcing rendering. The source guard includes ampersands because CommonMark decodes character references in fence info. This conservative guard may render false positives eagerly, including ordinary URL queries; it deliberately avoids duplicating a CommonMark parser.

Entry height estimates use assistant/thinking source independently of whether a derived cache is warm. Search remains rendered-text search; visible height, source offsets, wrapping, copy, links and diagram affordances are exact. Existing layout invalidation/anchors and viewport/overscan correction remain responsible for approximate offscreen heights. Do not change cadence, writer scheduling or ready semantics.

Adversarial checks: held LaTeX suffixes; Unicode/tab/CRLF; lists/tables/code/math/links/Mermaid; raw/pretty copy before first draw; width/theme/raw changes; late chunks/repeated finish/clone; images disappearing/changing between finish and first display; empty/internal image markers; reasoning timestamps; root/child notification ordering; estimates and exact viewport anchors. Compare eager/deferred output and source maps, not just text counts.

Use same P0 instrumentation and retained binaries,3 AB/BA release pairs in default-off mode as primary performance evidence; detailed logs only attribution, because observer/cadence effects are measurable. Repeat modern128/512/2048,slow512 and loading Ctrl+D. If512 becomes faster than two eligible paints, adapt the progress test to real replay duration rather than add artificial playback delays. Report floors/remaining root Timeline reread and image-scan costs; do not claim allmessage types become equally faster.

Source estimates exposed an existing navigation assumption: page selection ran before newly revealed estimated entries became exact. Before selecting a page edge, reuse the existing bounded viewport settle, then choose the exact edge. No eager history measurement. A sticky prompt may itself wrap to a different header height after resize; compare logical anchors/visible rows against eager control rather than demand an unrelated following entry keep the same physical row. Dedicated no-sticky tests isolate the entry-anchor invariant.
