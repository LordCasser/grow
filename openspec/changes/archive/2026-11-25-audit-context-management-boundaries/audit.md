# 上下文管理架构审计

审查对象为 `49d53af35` 上工作区内的会话分流、回放历史预压缩和 Skill 行改动。对照 `model-sampling`、`context-compaction`、`client-surfaces` 三份契约。原事故的用量对齐、14 次隔离 HTTP 重放与既有 Rust 测试见[会话分流验证](../2026-11-25-isolate-sampling-session-affinity/verification.md)。历史请求未发送给真实模型。

## 已确认的职责边界

| 决策 | 当前所有者与依据 |
| --- | --- |
| 普通采样向哪个上游会话发请求 | ChatState 在构造请求时用 Timeline、rewind 锚点、模型路由和 continuation epoch 派生分支键。对现场两条 Timeline 再次只读统计，323 与 315 条带主请求来源投影的记录分别只出现过一个 epoch。普通追加和原请求重试沿用其身份，fork、rewind、历史替换及冷启动可获得新身份。 |
| 一次后台或旁路操作的重试 | Shell 的 `SidebandRun::run_provider` 使用操作自身的 UUID。实际请求在进入 Sampler HTTP 传输前确定其身份。显式路由配置的同名头优先；将路由固定到常量会主动覆盖自动分流。 |
| 压缩应不应该启动、请求能不能发出 | ChatState 提供当前请求估值与冷恢复消息估值；Shell 使用二者决定是否预压缩。提供方用量、当前请求的输出预留和硬窗口准入仍各有自己的依据。状态栏的 839,800 是提供方实报的输入。下文测到的重复计量影响本地估值。 |
| 展示加载了什么 | 模型工具调用的 `raw_input.resource` 已携带请求的相对路径。Pager 可用它区分同一 Skill 的不同资源，展开的来源来自加载结果。普通实时更新及未分片的历史可沿用同一投影。 |

## 需要收敛的行为

### 1. 回放估值把模型触发的 Skill 正文重复计入

`sampling-types/src/conversation.rs` 的 `project_portable_history_with_indices` 同时保留真实工具交换和已提交的 `SkillLoad` 事实。Chat Completions、Responses 和 Messages 在各自的协议转换里都会跳过 `SkillLoadSource::Model`，正文已经在真实 ToolResult 中。`chat-state/src/actor/state.rs` 的 `estimate_wire_items` 却对这类事实调用 `estimate_skill_load_tokens`，又按带完整正文的工具结果计一次。原有估值偏差随新的回放阈值检查直接影响前台摘要。

按会话 A 的已选 Surface ID，在临时构建中调用生产 Rust 回放投影、计量函数和三个协议编码器。仅从投影副本去掉模型来源的 SkillLoad 标记，三个后端的请求 JSON 均逐字节相同。下表为同一字节估算口径下的 tokens，非提供方 tokenizer 的测量结果。

| 请求证据序号 | 模型 Skill 条数 | 现行回放估值 | 重复计入 | 扣除此项后 |
| ---: | ---: | ---: | ---: | ---: |
| 4503 | 43 | 735,560 | 101,248 | 634,312 |
| 5166 | 50 | 839,377 | 116,937 | 722,440 |
| 5486 | 54 | 883,270 | 125,254 | 758,016 |

1,048,576 窗口的 80% 触发点为 838,861。后两处都足以改变前台判断；末处仍达到 70% 后台阈值。序号 4503 则会改变 70% 的后台判断。修复应作用于请求可见项的估值，保留原始 Timeline 事实与原始 Surface 的计量用途。回归需同时包含模型来源、用户来源以及该 Skill 对应工具结果被剪裁后的情况。

### 2. 一次摘要完成后，下一步可以只压缩上一次摘要

已有回归 `portable_summary_with_a_large_retained_exchange_dispatches_before_resummarizing` 验证了同一步能发出主请求，且下一候选区可以只含刚提交的摘要。`turn/mod.rs` 每轮重新设置 `compaction_handled`。在独立 checkout 中沿用该用例的 100,000-token 窗口和受保护的 105,000-token 工具结果，让第一条主响应真实调用一次 `read_file`，下一条主响应结束回合。记录到四个 HTTP 请求按“摘要①、主请求①、摘要②、主请求②”发送。第一次替换提交在事件 23；第二次替换提交在事件 56，其唯一被替换项是 `(23,0)`。第二份摘要的请求包含第一份摘要，未包含新增的读文件结果。

对预防性压缩，候选选区至少应覆盖一条上次摘要之外的新可替换证据。这个判断属于选区与提交边界，已有 Surface ID 能证明是否取得进展。应保留既有的“旧摘要加新证据”滚动合并；人工请求与硬溢出恢复有各自的语义。验收用连续工具 Step、受保护大尾部验证摘要派发次数和替换范围。

### 3. 预防性摘要失败时，能够发送的主请求仍会停止

在同一独立 Shell 夹具中，只有回放估值触发预防性压缩，模拟摘要服务返回 400。该回合只发出一个摘要请求，普通请求发出零次。随后用同一 Actor 调用现行硬窗口检查，通过时为 3,598/100,000 tokens。保持历史与服务器，抑制预防性压缩后，下一次主请求成功。两个临时 Shell 探针均通过，使用 Rust 1.93.1，未调用真实模型。

现行契约对「没有可用选区」已有让行规则，对由提供方拒绝、实际超窗或持久化失败导致的恢复已有严格边界。`finish_auto_compaction_error` 只在特定无选区错误时重做准入，尚未规定仅由回放估值触发、摘要服务不可用、主请求明确装得下时应否继续。这是降级策略的决策点。若允许继续，应保留摘要失败事实，并执行原有主请求硬准入、取消、存储和预算约束。

### 4. 冷恢复与网关首包的可用历史不同

冷启动创建新的 continuation epoch；即使 Timeline 相同，普通请求的分支键也会变化。Responses 适配器当前发送显式历史片段，`previous_response_id` 为空。这个边界允许压缩提交和 rewind 放弃已经失效的上游状态。

事发版本的 AGY 插件在全新连接首次构建提示时，默认只有 114,688 **字节**的文本预算，系统说明、当前 turn 和框架文字还会占用其中一部分。可继续使用的上游连接或成功恢复的上游会话走续接分支。历史超过首包剩余空间时，桥接可截短工具块并舍弃旧消息。Grow 的 1M **token** 窗口与网关首包字节预算是两个约束。原事故中的隔离修复能够消除跨会话争抢，端到端的冷恢复保真还取决于上游实际接受的重放内容。验收时应读取桥接最终使用的提示，核对早期目标与近期工具证据是否都能读到。

本机直接执行已安装插件的 `canonicalBody → foldSplitCalls → renderInitialPrompt`。输入事发时的实际请求，Step 25 的历史从 58 条、346,015 字节降到 23 条、103,250 字节；Step 292 从 592 条、3,037,257 字节降到 29 条、102,725 字节。两处条数、字节均与事发日志相符。作为对照，另一组 12 条、70,166 字节历史搭配 62,000 字节系统说明，说明进入首包时保留 9 条；说明已由上游单独安装时保留全部 12 条。这是特定桥接版本和配置的实测行为。

### 5. 折叠行的窄屏与分页恢复

- 在 64 列终端，`Skill software-engineering · references/directory-structure.md` 的标题需要 62 列，追加 `  Loaded` 需要 70 列。通用工具行的 `collapsed_line` 只在标题和整个摘要都放得下时追加摘要，随后从右截断。新标题会挤掉状态，长公共目录也能盖住两个文件的差异。Pager 应为状态留出宽度，再决定资源路径显示哪些部分。验收覆盖成功、失败以及两个同前缀文件。
- Shell 历史存储在工具展示载荷超过 1 MiB 时分片。`storage/jsonl/tool_fragments.rs` 的 Header 与 Body 均未保留 ACP `_meta`，Pager 的 `history_window::decode_tool` 重组时也没有恢复它。真实 Skill 使用 ACP 通用 kind，另由 `_meta.grow/tool.kind` 标识；分页加载完整后仍可退化为普通工具行。一个 800,000 字节的合法 UTF-8 资源经 JSON 转义就能跨过分片门槛。应在工具展示分片的往返边界保留解释该行所需的元数据，用完整分页恢复比较其与实时行的名称、资源和状态。此缺口早于资源标题改动。

相邻的既有展示问题有两个独立入口。资源请求同时带非空参数时，执行端在 `raw_output.message` 返回拒绝原因，Pager 却从 ACP content 读取原因，展开后只给出通用失败。不同命名空间中的同名技能可分别以限定名称启动，成功结果里的裸名会覆盖原始调用名，导致两个同资源名的终态行再次相同。普通 Pager、分页历史和 minimal 输出是不同验收入口，已有 80 列折叠单测未覆盖完整 PTY 或 minimal 的 Truncated 模式。

### 6. 缓存复用与有状态对话是两个不同的承诺

`ConversationRequest.prompt_cache_key` 对调用方的定义是供应商前缀缓存路由。当前各 Conversation 适配器将存在的缓存键直接用于 `X-Session-Id`。仓内普通请求恰好给它一个按分支变化的键，recap 在实际发送时有 Sideband 身份覆盖。公开采样接口允许两段无关会话显式共用同一缓存键；此时也会共用传输会话头。后续接口应当显式接收操作所属的分支或 Sideband 身份，保留现有生成值即可，无需再持久化一个会话 ID。验收反例为相同缓存键、不同会话归属的两个请求。

## 演进顺序

优先修复估值与发送内容的语义偏差，以及成功摘要后缺少进展判据的问题。二者改变何时会发起或重复发起有损操作。然后明确预防性维护失败的策略，并给冷恢复单独设立网关验收。Pager 的窄屏和分片问题可独立处理。缓存键与会话归属的独立传递由现有请求边界承载。

普通 Step 在后台边界和采样前都可能重新构造冷回放投影。此次审查未测出每步新增耗时；性能优化可先测相同 Surface 的重复计算成本，再决定是否在已有版本边界复用。现有证据不要求引入新的上下文管理服务或持久化计数器。
