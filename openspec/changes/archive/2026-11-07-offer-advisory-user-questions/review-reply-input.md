# 迟答输入的独立审查：真实消费入口

父与只读reviewer `01a1b13f-830d-78a0-9681-9bb159c69a49`在21项单元/调用层测试green后继续核正常产品路径。以下为当前源码可证的两个独立缺口，分别实施与验收；不把手动dispatch canonical回调的测试当作其生产触发已接线。真实PTY正在运行，动态结果另记。

## U1 · P2：正常完成未触发答复接纳观察

触发：卡片编辑提交，经canonical Absent释放普通Send，服务端正常接纳并结束。`prompt.rs::reconcile_advisory_reply`把卡设Unconfirmed；产生QueryInputAdmissionStatus的路径只有首次Reply、Submit预查及错误恢复，没有正常成功通知。`handle_prompt_response`正常Ok分支走finalizer/drain；durable TurnCompleted从session_notification进入shared finalizer和`AppView::apply_terminal_outcome`，同样没有问答接纳观察。因此正常完成后，卡会一直显示未确认，除非用户再次点Reply。

违反：只有canonical事实可认定已答，但确认入口必须真实接入完成链，不能把产品永久留在unknown、依靠用户补发隐藏查询。Blocked/Handled等没有新的工具回答，终态仍需通过同一观察入口决定。修复归Pager输入owner：在现有first-wins收尾之后，以确切结束prompt_id和owner查原卡，触发既有canonical query。覆盖PR赢/durable赢以及另一rail迟到，不能重复finalize、通知或drain；不依赖active tab、optimisticbubble，不新建后台轮询/持久表。单次必要观察可失败为Unconfirmed，显式Check可再查询。

通过：实际Submit→Absent→Send（首次输入现由U3直接普通Send）→真实PromptResponse Ok或durable TurnCompleted（分别先到）产生正确identity查询；对端返回canonicalAllowed/Consumed/Handled→Accepted，Blocked/Dismissed→Rejected，错误→Unconfirmed。两rail交错保既有一次收尾。fresh CLI真实PTY在无需额外Reply点击时显示已答，日志旧tool仍只有原单次结果。

后续落点已核：PR赢家在handle_prompt_response的ViewerFinalized门之后，durable赢家在AppView::apply_terminal_outcome的ViewerFinalized分支。现有 `session.finalized_prompt`已保结束id，无须为此新建终态表或改变TerminalOutcome公共形状；在maybe_drain_queue可能启动新Turn前取得结束id。通过原full identity helper定位卡，只在有效nonterminal卡产生一次canonicalquery。PR迟到只metadata merge、durable重复Ignored不得新增finalize/drain。原Err+failed_draft已经产生query，不重复加第二份；错误路径与普通observer仍可保持unknown而不自动重送。若F3 AdmissionReplay返回既有状态，须区分这是RPC观察结束而不是新业务Turn完成；其Pager消费证据随U2同身份重试验收，不借正常finish掩盖。

## U2 · P2：实际Check入口无法重送未接纳的冻结答复

触发：首发在TurnSubmitting遭遇未知ACK，`restore_failed_input_draft`保留composer/inflight；自动canonical Absent把原文克隆到requires_review队列并保inflight。实际卡片r/双击只发Query；回调仍因has_inflight为true保持review，不drain且不打开editor。唯一释放idle uncertaininflight的代码在Submit action，而正常UI只能在editor里生成Submit，此时editor已不能打开。重复Check永远不重送。普通composerEnter排到review后面；通用queueedit会撤销prompt_id成为新输入，不能作为本身份的重试。

违反：用户明确重试且canonical确认Absent后，应能通过可达入口按原正文/身份再提交。修复仍归输入owner，复用卡上一次open_intent来区分用户此次点击和自动错误观察，或既有同等明确retry入口；不能让自动Absent发起无限重试，也不能要求改选产生新text。交接固定原QueuedPrompt/uncertain draft所有权，card无正文副本。非Absent保冻结且只查询；terminal只读不重入。

通过：真实Action首发→实际PromptResponse Err→自动查询Unknown/Absent不发送；随后实际QueryAdvisoryReplyAdmission action（代表card r/双击）→匹配durableUnknown/Absent，在idle且该身份没有活跃派发时按F3重试原payload/id一次，不需要伪造Submit。再次快速点击/晚回调不同时发送第二份；Submitted只查不发，terminal只读，transport/parse/timeout/unavailable错误不能授予发送。测试覆盖用户改choice文本不能替换冻结payload，原普通composer稿保留，sourcechild归primary。终端产品链对这一失败状态的可达控制需与普通成功PTY区别记录。

U3后固定实施约定：原一次open_intent表示这次明确用户卡片操作；在读取该意图前保card单调资格，只有匹配durableUnknown/Absent、存在既有冻结正文、sessionidle且该id无活跃RPC/Turn时可释放原reviewqueue/inflight。自动观察不含此意图，永不重送；存在未发送ready首发row时沿原普通FIFO资格，不生成第二份。未知不被解释成确定未提交；安全性由服务端F3对相同inputid+immutablepayload的串行新接纳/原状态观察/冲突拒绝提供。UI提示说明原答复可检查或重试，不能让用户误以为可以改正文复用旧id；可只改原Unconfirmed提示文字，不为提示新建持久状态。

F3的AdmissionReplay是该重试功能实际会消费的对端结果。父核Shell `build_admission_replay_meta`返回 `sessionId`、`promptId`、`grow/inputAdmission:{inputId,status:{status,...}}`，没有usage、Working/Idle或TurnCompleted；现Pager没有消费该字段，通用PR会误按EndTurn结算本地TurnSubmitting。此处必须在匹配原retry的观察结果时只退休该本地提交占位/查询状态、触发既有canonicalquery确认card，不产生新TurnCompleted marker/通知/usage或清理另一真实foreground。card的成功仍取qualified durablequery，不直接把meta回显当已答。元数据不符或失败保持原被冻结正文、展示未确认，不走假成功finalizer。复用现有未落地提交退出/readonly observer习惯，最多增加本输入owner内的私有消费helper，不新增公开replay协议或全局状态表。验证实际重试后同payload AdmissionReplay各canonical状态与普通新Turn成功分开，重复响应不触发新的业务收尾。若原reviewrow挡住后面的正常ready输入，canonicalterminal删除原row后应沿既有idle/editing/reconnect资格继续drain下一项；不可借此重新派发原terminalid，也不可中断另一真实foreground。

## U0 · P2：canonical查询没有接入ACP顶层路由

fresh CLI的实际r查询诊断日志 `advisory_initial_reply_unknown.rpc.log:19–20` 显示正确sessionId和稳定promptId，但RPC返回 `Method not found: unknown ACP extension method: grow/input/admission_status`。父核 `agent/mvp_agent/acp_agent.rs` 顶层ext_method白名单：包含queue/prompt_status等，却没有这个已在session_admin::handle注册的分支。当前UI的Unknown先来自transport error，**尚未实际收到下文U3的UnknownUnconfirmed响应**；此前仅凭屏幕对其wire原因的推测由本证据纠正。

修复归Shell ACP分派owner：把现有方法路由至现有session_admin handler，保原typed请求/原始response envelope、会话资格和boundedread语义，不加通配fallback。通过真实connect_agent_v1/connect_client_v1/MvpAgent/ext_method调用，而非直接调用handler，验证不再MethodNotFound且身份/source/status正确；已有session缺记录按原契约Unknown，不能借此路由修复改成Absent。此项独立旧红/新绿并核常规runtime准入回归。

## U3 · P2：首次答复依赖一个不会出现的Absent

U0目前阻塞实际RPC更深结果；独立于它，父核已有producer与consumer的静态决定性分支：已有session内找不到该prompt的durable输入，故意返回UnknownUnconfirmed，因为旧RPC仍可能在mailbox/首次提交中。只有session本身不存在才返回Absent；把不存在的owning session当正常答复前提也不成立。此前A/B设计把Unknown一概冻结、只Absent编辑/派发，consumer前提错误。应修consumer，保留F3观察语义；不能把generic缺记录静默改成确定未发送。U0修好后先用真实route响应验证此判别，再实施consumer修订。

架构修订依据是已归档F3的真实接纳边界：`input_id_for_prompt(session_id,prompt_id)`决定唯一输入，`input_admission_gate`串行接纳；已记录的同payload重试只观察原lifecycle，不重复Hook/queue/Turn；不同payload同id被拒绝。**普通首次输入不需要先证明全局不存在**，实际写入由这个owner做原子判定。

首次卡片查询收到匹配的durable UnknownUnconfirmed（合法观察，不包括transport/parse/timeout/unavailable错误）时：若本地没有该稳定id的冻结queue/inflight，允许打开本地编辑器；不宣称canonical不存在或已答。若找到冻结正文则仍不开放改选编辑。提交新答复时，先固定stableid和完整原文，再走普通literal FIFO→既有checkpoint→F3准入；不以再次查询的Absent作为新输入前提。已知terminal只读，Submitted保持观察，错误不猜默认可发。该修复不新增wire、backend、公共状态或card正文副本。cold卡query若找到Accepted/Rejected仍不可编辑；未记录的并发另客户端请求由同id+payload校验处理，冲突明确失败保文本，不能再换body覆盖原身份。

通过：实际QueryAdvisoryReplyAdmission→合法Unknown→本地editor→真实Submit→一次普通Send；falseUnknown并非缺省成功，所有错误状态/Submitted不打开；已有冻结payload的Unknown不得进新editor。真实freshCLI主测试必须进入编辑/提交阶段，保源/题目/推荐/实际answer，oldtool不再结算；F3同id同payload观察/异payload冲突回归继续通过。

Available投影现表示本地编辑可用，不等于canonical Absent事实；canonical Accepted/Rejected仍只有真实接纳观察能设置。原交接中“Unknown一律不开编辑”和“首次Submit先query只Absent发”的限定由本修订替代，其他失败、终态和不可变payload规则保持。
