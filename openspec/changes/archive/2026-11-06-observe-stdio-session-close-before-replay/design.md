# Design

`forward_stdio_line_to_leader` owns the actual outgoing boundary; `cache_outgoing_acp_state` owns method parsing and replay-state mutations. Remove the duplicate substring allowlist in the forwarder and call the existing parser once for every nonempty line before its existing bounded send loop. Irrelevant methods/malformed JSON remain cache no-ops and forwarding remains unchanged. Reuse existing `remove_session` and primary-session clearing. No second parser/state owner, no close response correlation or pending-new changes.

Tier 3 invokes `forward_stdio_line_to_leader` for initialize, two loads, then one close and records forwarded messages on the first mock leader. Snapshot the resulting replay owner and run `replay_acp_state_after_reconnect` against a replacement mock leader that answers initialize/load. Assert the closed ID is never loaded, the other ID is loaded exactly once, and the primary restored ID refers to an open session. Cover both grow/session/close and _grow/session/close in a compact paired test; existing helper unit tests alone are insufficient. Include irrelevant prompt content mentioning a lifecycle string to ensure parser method identity remains the owner.
