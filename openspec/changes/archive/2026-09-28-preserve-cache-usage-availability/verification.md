# Verification

## Protocol evidence and mapping

The three wire boundaries were checked against their locked types and captured-shape tests. Chat Completions uses optional `prompt_tokens_details.cached_tokens`; DeepSeek top-level hit/miss fields are accepted only when their sum matches full `prompt_tokens` and do not override a conflicting primary count. Responses uses `input_tokens_details.cached_tokens` plus `cache_write_tokens`. The locked async-openai `ResponseUsage` does not model the write field and requires read/reasoning details, so the terminal-event decoder supplies typed zeros only to decode missing details and preserves actual read/write presence in internal response metadata before usage normalization. Messages retains start/delta presence independently; a delta's explicit zero overrides start, and full input is unknown until uncached, read and write components are all known.

`CARGO_BUILD_JOBS=2 cargo test --locked -p sampling-types --lib cache_usage`: 1 passed (missing, explicit zero, positive alias, conflict and invalid read count). `CARGO_BUILD_JOBS=2 cargo test --locked -p sampler --lib cache`: 4 passed, including Responses nonzero write with missing read and Messages delta override. `CARGO_BUILD_JOBS=2 cargo test --locked -p sampler --lib messages_missing_bucket_keeps_full_input_unknown`: 1 passed. A completed Messages response lacking a required full-input bucket is not resampled by the usage parser.

## Settlement, restore and Goal

`CARGO_BUILD_JOBS=2 cargo test --locked -p shell --lib usage`: 77 passed after updating an existing Messages mock fixture to report explicit zero cache buckets. Its prior omission correctly made full input unknown and closed subsequent exact-budget admission. The run covers main/Sideband settlement, child fold, late and incomplete usage, Goal budget and classified components. The specific Goal regression `missing_cache_read_keeps_exact_goal_total_but_unclassified_input` passed: full input plus output remains exact while missing read input is unclassified. Shell's Messages compaction Sideband observes a bill only after all three input components reconstruct full input; otherwise its attempt remains incomplete.

## Presentation and limits

Pager `/usage` uses the read-known denominator and separately displays coverage; its 100/900 test, zero denominator, read-known/write-unknown and incomplete ledger cases passed in targeted unit tests. The normal status shows cache N/A when read coverage or total consumption is incomplete, while keeping exact total tokens for cache-detail-only gaps. ACP/headless preserve full input, known cache buckets and unknown-call counts; headless uncached `input_tokens` is `null` when either bucket is missing. The `ResponseStarted` preview pipeline now carries optional read/write fields through Shell and Pager instead of changing missing to zero.

`CARGO_BUILD_JOBS=2 cargo test --locked -p pager --lib usage`: 81 passed. An earlier run exposed an obsolete expectation that an incomplete aggregate would present an unknown cache-write count as zero; its assertion now checks for `null`. `CARGO_BUILD_JOBS=2 cargo test --locked -p pager --lib headless_response_started_parses_per_response_fields`: 1 passed. `CARGO_BUILD_JOBS=2 cargo test --locked -p shell --lib sampling_attempt_delivery`: 1 passed. `CARGO_BUILD_JOBS=2 cargo test --locked -p shell --lib project_result`: 4 passed, including known full input with missing cache detail. `CARGO_BUILD_JOBS=2 cargo check --locked -p shell -p pager`, scoped `cargo fmt`, and `git diff --check` passed.

The delta scenarios were checked against the fixtures above and targeted source paths: missing/zero, read/write independence, aliases, Messages start/delta and missing full input, exact totals with missing classification, retry/dedup and restore, Sideband/child/Goal settlement, read-known denominator, UI/headless partial values, and no extra provider policy. Broad crate suites were not run; the targeted tests and package checks cover the changed boundaries.

No price, provider cache parameter or additional billing store was introduced. There is no provider performance claim in this verification. `cargo clean` removed 37.3 GiB of build artifacts after Rust verification.
