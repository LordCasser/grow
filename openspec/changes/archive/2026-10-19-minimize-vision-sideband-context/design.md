# Design

The auxiliary request is constructed from one user message containing the fixed prompt and the target image parts. It does not include conversation history, tool or Skill context, or the source message text. The Sideband continues to record the source Timeline reference locally; its prompt identity and cache key use the fixed prompt so completed work can only be reused for the same image/source and prompt.

The existing durable ImageProjection, OCR fallback, cancellation, timeout and provider rejection paths remain in place. Recovery progress and outcomes use one typed operation row with English status text; OCR output and vision descriptions retain the language returned/read from the source. The canonical Chinese unsupported-image replacement remains a typed Timeline invariant.

The recovery UI is a mutable lifecycle operation rather than a sequence of notices. Shell emits typed updates carrying one operation ID and owner prompt across vision and OCR phases and a terminal result. Pager projects that identity to one dedicated ordinary scrollback operation row; the shared ScrollbackState also drives Minimal, so the live row can be redrawn and committed in its final form without a second UI surface or a fake ACP tool call. Historical updates fold by operation ID. The driver's prompt response is an exact-prompt terminal boundary and may settle its row before the durable turn notification; a stale terminal for another prompt has no effect. Turn-owned reconciliation settles rows for the ended prompt, while a live reconnect preserves the operation owned by the authoritative active prompt and settles stale historical rows. Offline read-only projection stops any remaining animation at snapshot EOF with an incomplete-at-snapshot label, without modifying history.
