# Design

The sideband Timeline remains the source of its request/result/evidence, outside the model-visible Surface. The owner session Timeline receives compact billing observations because `ChatStateActor` already owns the live and restored UsageLedger. Before the first poll of each real provider request, persist an `aux_attempt_started` observation with `(sideband_id, attempt_no)`, frozen catalog route model and optional prompt index. An exact duplicate is idempotent; a conflicting identity fails closed. A started attempt without terminal usage at cold recovery makes the originating usage segment incomplete. Admission precedes the provider poll, so a crash cannot silently restore an exact zero bill for an in-flight attempt.

After each request reports usage or a confirmed no-dispatch, persist `aux_attempt_settled` with the same key and normalized `TokenUsage`, optional cost/duration. Missing usage after dispatch persists an unknown settlement. The ChatState actor acknowledges the immutable observation before folding it. An uncertain ACK retries the exact payload; a different payload for the same key is a conflict. Sideband retries settle their previous attempt before another provider admission. Cancellation and owner drop use the same detached settlement fence, retaining session activity until it is durable or reporting incomplete shutdown. The successful Sideband Result is never folded as a second bill.

`UsageLedger::record_auxiliary_call` folds known usage into totals, by-model and the local owner Agent, but leaves `main_loop_model_calls`/`numTurns` unchanged. If the captured prompt is still current, it also folds into that prompt; otherwise it only changes lifetime usage. Child Sidebands enter the child ledger, then the existing terminal child bill enters the parent exactly once. The parent never independently folds a child's Sideband observation. Unknown usage marks the relevant ledgers incomplete and hides exact cost.

The normal `ConversationResponse` path keeps full token details and reported cost. The shared compaction helper's existing per-request meter reports a narrower SidebandUsage value; it must settle each actual wire attempt, including retries, without treating one compaction operation as one bill. A usage-less success is unknown unless existing evidence proves the provider was never dispatched. Tests cover retries, failure, cancellation, duplicate ACK, cold restore with an open attempt, parent-child fold and `/usage`/headless projections.
