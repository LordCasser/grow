# C3 场景与测试映射

本表按当前 delta specs 核对测试名称、共享 golden fixture 和 Pager 逐 prefix 投影测试。覆盖映射不等同于测试通过。final22 Shell scoped groups 为 19 组、1331 passed、0 failed、4 ignored；final21 Pager scoped groups 为 9 组、755 passed、0 failed、1 ignored，pager-pty-harness 普通单测 96/96。final21 correctness oracle 的 4 个 profile 全部通过；fork replay memory gate 为 1.714116x（原 `<2x`），roundtrip、load peak RSS 与 e2e RSS gates 通过。final21 CLI #01–12、#14 均通过；#13 的最终真实工具/cold ACP 组合由 final25 通过，旧失败保留原日志。Orphan seq40–44 证据记录了旧清理顺序关闭新 notification Hook；final21 的真实 orphan recovery CLI #12 与独立 Hook ACK 回归均通过。final paired 使用最终 build 的复测已完成，完整结果见 paired-analysis；旧 root paired 数据仅作中间证据。标为缺口的项目只在所列行为/边界确实没有直接断言时保留。

历史验证记录：build12 actor ACK-loss 与 session_state summary-version fixture failures 已在 build13 修复并通过对应 scoped groups。build12 CLI smoke runner 的前 11 项实际为 0 passed（ignored 未执行且 exact test 名匹配不完整）；该 runner 缺陷已由 final13-real 的逐项 `--exact --ignored` 执行纠正，不能把旧 build12 数字累计为通过。final13-real 的 1–7 项通过，#08 因 mock provider 配置缺失失败、#09–11 依主任务指示终止；后续单项结果只按各自日志记录，不推断整个 CLI 矩阵通过。

## 明确缺口

- preview byte-budget与慢 gateway已有 `actor/updates.rs::slow_gateway_exhaustion_rejects_preview_before_enqueue`、`buffered_independent_grow_obeys_preview_gateway_budget`；anchor、independent ACP/Grow append失败阻断 admission已有 `session/persistence_tests.rs` 对应故障注入。Remaining gap: 尚未发现同一个慢真实 gateway下交错多个 ACP/Grow生产者的端到端 PTY压力场景。
- replay barrier与cancel resync已有 `late_attempt_during_replay_pause_is_resynced_and_cancelled_release_unblocks_writer`、`replay_barrier_holds_new_appends_and_cancellation_releases_them`；物理 cold/read-only replay下已提交响应+later independent顺序有 `response_projection_production_read_only_cores_preserve_unified_timeline`，Pager tail保持/继续流由对应 reconnect测试覆盖。仅 response 恰在 authority 与物理截点捕获之间完成的精确竞态未单独命名覆盖。build20 cancelled-leader PTY 验证了先 admitted 的 T1 在取消 T2 后保留；它不模拟 admission 后的客户端编码/交付失败。
- Offline Transcript 的 ImageRecovery EOF 静态化由 `transcript_projection/tests.rs::unfinished_image_recovery_is_static_at_offline_snapshot_eof` 覆盖（该 test 在 build12 transcript-projection group 已执行并通过）；同一 row 终态由 `image_recovery_updates_reuse_one_row_and_terminalize_during_replay` 覆盖。Pager cursor reconnect同一 image row、EntryId稳定、terminal忽略late progress已有 `cursor_reconnect_merges_image_recovery_completion_into_original_entry`，child replay和matching TurnCompleted分别由 `child_image_recovery_full_notification_path_replays_one_terminal_row`、`child_turn_completed_settles_only_its_matching_image_recovery_prompt`覆盖。image EOF 当前不是缺口。
- ToolEvent lifecycle、ACP ToolUpdate.rawOutput 和模型 ToolResult 的 root 通用工具组合现由 final25 直接验证，见下节；其他工具 producer/子树组合仍未穷举。

## 最终工具组合补验

`final-25-tool.log` 的真实 CLI4 用例 `sleep_tool_records_multi_second_dispatch_duration` 为 1 passed。它实际运行 2 秒命令，并核对同一 call ID 的唯一 ToolEvent success、工具 call/rawInput → completed ToolCallUpdate/rawOutput → final assistant 的投影全序，模型 Surface 的 call → ToolResult 完整正文 → final answer 顺序，以及 fresh ACP cold load 与已验证 projector 的完整 assistant 文本相同。标记文件只有一次写入，load 前后 inference endpoint 请求数不变；原 1500ms 时长下限未放宽。通用 ToolEvent 只承担生命周期，不要求它重复保存 rawOutput 或 ToolResult 正文。该用例填补 root 通用工具三个来源合用与恢复不重派发的直接缺口，不穷举所有工具 producer/子树组合，也不模拟 admission 后客户端交付失败。

旧 #13 在 FIFO mock 下未得到 ToolCompleted，原日志不足以确定请求竞争的具体先后；改为已有 foreground matcher，保证工具脚本只能由真实主回合请求消费。首次组合测试误要求 metadata-only ToolEvent 含正文，按实际生产契约纠正；再一次失败来自 headless 的 canonical `/private/var` cwd 与 ACP 测试 `/var` namespace 不同，现按持久 Summary.info.cwd 加载，并验证它指向同一隔离工作区。中间失败保留 `final-23-tool.log`、`final-24-tool.log`；没有改生产路径掩盖测试问题。源码/driver/CLI hashes 见 `final-25-tool-context.json`。
