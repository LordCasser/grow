# Design

The viewer loader is the single point that creates its copied source and display buffers. Give it a process-wide reservation account with a fixed aggregate ceiling. A path load reserves its maximum encoded-source allowance before reading; a memory load reserves the known copy size. After header validation, increase that reservation before conversion to cover source bytes, a conservative decoded/conversion workspace derived from bounded pixel count, and the conversion-output cap. A protocol that only copies the encoded source reserves two encoded copies. If admission fails, return the existing `Failed` result before the next allocation. The reservation shrinks to actual retained `Vec` capacities after conversion and travels with `LoadedImageData` into `ImageViewerState`.

The reservation is released by ordinary drop: failed conversion, ignored stale `TaskResult`, viewer close/reopen, and Agent/child teardown all converge on the same owner. The UI thread never waits on the account; it already receives a completion and displays its normal failure toast. The source `Arc` in the composer is preexisting input ownership and not charged as a new viewer allocation. OS decoder and macOS `sips` allocations outside Grow's buffers are measured separately and remain an explicit limit of this budget.

Use an injectable budget in loader tests so concurrent test execution cannot affect the aggregate admission assertions. Verify admission rejection before conversion, held-buffer accounting, stale result drop, and release after viewer close. Keep the existing owner-ID check; it prevents an old result from replacing a newly opened viewer.
