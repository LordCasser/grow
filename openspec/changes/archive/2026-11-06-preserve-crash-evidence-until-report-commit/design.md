# Design

Crash-handler owns raw recovery and report publication; CLI owns startup installation. Freeze the shared interface as `check_previous_crash(&Path) -> std::io::Result<Option<CrashReport>>`. Missing and empty raw files return Ok(None); other read errors propagate. Nonempty malformed blobs return InvalidData without consumption. Existing valid report fields remain. Update library docs, tests and the single production CLI caller together; no compatibility wrapper.

Publish `last-crash-report.txt` and the existing history report before removing raw evidence. Each publication uses an exclusive sibling temporary file, sets owner-only permissions before writing on Unix, writes and syncs the file, atomically replaces the destination, and syncs the containing directory where the existing OS interface supports it. Reuse the workspace tempfile dependency rather than hand-rolling temporary naming/cleanup. Windows limitations must be explicit rather than blindly attempting a Unix directory open. Both promised primary and history publication must succeed; pruning remains at the existing MAX_HISTORY bound after the new archive is present. Protect the just-published history path from that call's pruning: choose the oldest other report paths until the bound is met, so recovery of an older timestamp cannot delete its own newly committed archive before raw consumption. Publication errors propagate and leave the original raw bytes available, including when one report was already published. Cleanup after both durable reports is a separate post-commit operation: failure must remain observable but cannot invalidate those reports. Do not claim an all-or-nothing transaction across both report paths.

On recovery Err, CLI emits a concrete warning and leaves the already installed terminal-restore-only handler active; it does not call full install, since that path truncates the raw file. On Ok, retain existing optional report notice and capture configuration. Never delete real user evidence in verification; all cases use owned temp roots.

This fix does not change CrashBlob schema, raw path identity, signal-safe capture, symbol resolution, multiprocess claiming, history naming or report format. Those independent PB-05/06 changes follow only after this publication contract is accepted. tempfile is an existing workspace crate, promoted to the required runtime dependency for atomic publication; no new service, registry, config or journal is added.

Tier 3: actual public recovery with a valid raw blob and primary path blocked, history path blocked after primary success, success/retry preserving the original crash identity, unreadable/nonempty malformed evidence, Unix private modes, and existing crash capture integration. Verify CLI recovery failure cannot run the truncating installer (through a bounded startup test or actual isolated CLI). Add sync failure injection only if required to prove the supported barriers, scoped per invocation/test rather than a global switch. Parent reviews publication/consumption ordering and startup caller and runs the integrated CLI check/build after candidate delivery. Cargo is serialized; implementation prepares in an isolated worktree and exports owned files only.
