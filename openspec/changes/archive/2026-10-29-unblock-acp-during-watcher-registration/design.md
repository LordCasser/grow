# Design

Run blocking watcher construction through `tokio::task::spawn_blocking` and await its result from the LocalSet. Awaiting yields to the LocalSet scheduler, allowing the already-spawned ACP agent and bridges to process initialization while registration proceeds on the blocking pool.

Each blocking `JoinHandle` is awaited by the LocalSet startup future while the leader remains active. If cancellation wins, the helper drops the handle and returns promptly. Tokio's blocking task continues to own the in-progress constructor and its output; if the OS registration eventually returns a watcher, that result is dropped with the detached task output. The OS call cannot be cancelled, so it may continue occupying a blocking worker, and Tokio runtime shutdown can still wait for it. This change does not claim bounded cancellation of the registration call or bounded runtime shutdown. The skills watcher constructor returns the watcher and event receiver; only after the LocalSet receives both does a local task take ownership and consume events. The local task is explicitly aborted and joined at shutdown, so it cannot retain the watcher or ACP writer after the owning leader exits.

For stdio mode, start the ACP agent task before awaiting blocking skill watcher construction, and select between agent I/O completion and registration with the agent branch first. This lets EOF or another terminal ACP result end the LocalSet even if registration remains blocked; the detached blocking task retains and eventually drops its watcher result. If registration wins, start its LocalSet watcher consumer and await agent I/O as before. The consumer is aborted and joined when ACP I/O ends.

For the in-process Pager worker, configure the cwd path-update channel on the mutable agent before placing it in `Rc`, then spawn the ACP gateway before starting or awaiting either blocking watcher constructor. Once config watcher construction succeeds, apply queued cwd path updates and start both path and config event consumers immediately. Queue one existing `McpCatalogChanged { project_root: None }` update through that live config consumer. This refresh reads each session's current effective config by its own cwd, updates auxiliary policy, and uses the existing idempotent catalog merge. Skills registration proceeds independently while config events and catch-up remain live, so a blocked skills watcher cannot pause MCP policy/catalog refresh. Reuse the shell's shared `finish_blocking_registration` helper for both config and skills watchers. If cancellation or registration failure occurs after gateway polling begins, cancel local consumers and flush all sessions before returning; gateway completion wins a biased race against pending registration and follows the same flush path. Blocking OS registration remains uncancellable and its Tokio task owns any eventual result.

Tests block fake registrations with channels, prove ACP initialization and agent completion can progress first, verify prompt cancellation, and wait on an owner-drop handshake after releasing registration. Pager coverage uses the same gateway-versus-registration helper as the worker and a test-gated config watcher constructor to create sessions and edit global/project config during the startup gap, then confirms catch-up refresh and project isolation.
