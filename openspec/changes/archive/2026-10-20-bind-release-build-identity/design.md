# Design

Use the existing RELEASE_COMMIT job input as the official build label authority, not a second resolver or a global Git trust exemption. Require exactly 40 ASCII hexadecimal characters, normalize case, and display the first seven characters. Emit rerun-if-env-changed=RELEASE_COMMIT so changing the explicit source invalidates cached build output. A present malformed/empty/non-Unicode value is an error rather than silently falling back. Without explicit metadata retain the existing local Git behavior, including unknown when Git is unavailable.

Pass RELEASE_COMMIT explicitly to AlmaLinux and OHOS docker run and into CROSS_CONTAINER_OPTS for cross. Native macOS/Windows already inherit the job environment. Preserve workflow immutable checkout validation; a user-set build label alone is not provenance/security evidence. No blanket safe.directory=* configuration. Native smoke compares the complete version string; OHOS --smoke checks it when RELEASE_COMMIT is supplied, and requires nonempty GROW_VERSION alongside the explicit commit; manual smoke without explicit source metadata retains its existing behavior.

Tests must execute the actual production build.rs through a tiny offline Cargo fixture, including Git unavailable/ownership denied, explicit hash valid/invalid, Git fallback, and changing only the explicit commit on the same cached target. Use a real root/bind-owner mismatch container probe to distinguish Git ownership from missing Git. Test future-release smoke without invoking publication. Local Git HEAD/ref cache tracking beyond the explicit-release input is a separate issue if encountered; do not broaden this fix into a general version framework.
