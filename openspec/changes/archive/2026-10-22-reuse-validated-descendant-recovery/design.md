# Design

The root backend already owns a fully validated Timeline at the history emission frontier. Project only the compact spawn ownership/enrichment data required by descendant restoration, attach it to that exact load result, and pass it through the existing result path. Missing/invalid/unbound data must not be treated as a verified empty root; use the existing independently validated fallback or fail the relevant recovery. No global mutable cache.

For each visited descendant parent, combine canonical child spawn discovery and the ordered lifecycle/control stream using one pinned validated session read. Keep identity/path checks and full history validation before exposing its projection. Continue breadth-first traversal, source-local cursor/highwaters, subagent identity checks and canonical CWD/worktree enrichment. Never turn a missing or corrupt child into ownership authority, execution or a fabricated successful outcome.

Exact wire/type integration is selected after checking cold/resident/reconnect/fork callers and existing epoch cancellation. Tests will fix frontiers, mutate/append source after capture, mix wrong parent/session/seed, replay/live overlap and multiple child copies, then check full rendering and subsequent persistence. API details and any observed contract mismatch are recorded here before implementation.

Baseline CLI is built before production edits; added benchmarks are test tooling. Use a dedicated release target, actual compiler/executable/source hashes, warmed-cache fresh-process AB/BA pairs. Main TUI metrics distinguish first/last history, complete finalize and stable prompt; do not add nested phases. Root-only shows duplicate-root-read removal, valid nested/wide trees quantify descendant read reduction. Backend full-history, UI routing/control/media/copy/layout and actual cold tree resume remain correctness gates.

## Selected integration

Use a compact `DescendantOwnership` (session, physical cut/hash, child-id map of subagent id/prompt/cwd/worktree only) built at the exact Timeline/HistorySnapshot used by replay, before Timeline moves to actor bootstrap. No execution recipe or canonical response body is transported. Put it in the existing load-response meta key and carry it as a one-shot optional task-result argument through normal load, explicit resync and transport reconnect. Existing resync/reconnect generations remain the acceptance gates; normal load creates its own AgentId and uses the existing open-reload guard. Validate wire shape and canonical response/session identity; absent/malformed/foreign data takes the old fully validated disk fallback. The hash identifies the already checked cut, not a cryptographic proof against a malicious ACP server or a promise to detect later disk mutations without rereading.

Derive each descendant's ownership and ordered selected Grow notifications from one shared-read pinned capability, one full Timeline/history/evidence validation and the existing projector. Move selected notifications instead of cloning all replay rows. Keep the exact existing UI-intersection/BFS/enrichment/highwater semantics, including lifecycle owner vs security parent distinctions; no global cache and no retained snapshot after restoration. Root with a verified empty ownership map needs no extra read; absence is not emptiness.

Observed contract distinction: Pager's existing best-effort display traversal validates the parent facts and child entity/history, but is not the strict cross-ledger seed/result execution/tree-export reader. Some display tests intentionally contain presentation-only nested spawns without a canonical Domain spawn; those may be displayed but cannot authorize further traversal/enrichment. Do not quietly replace this path with `capture_tree_at` or claim it proves execution eligibility. Execution/storage/export seed/result checks remain intact and are regression-tested separately. Any independent policy strengthening is separate debt, not this performance change.

Additional benchmark observation: default-off PTY now records the first ready view (sentinel+model label+no Loading banner) before the fixed500ms stable interval; detailed full-finalize and last-history markers remain separate. This is test tooling only, not a readiness change.

Fixture correction evidence: the first chain fixture had Domain spawn/seed but omitted the independent Spawned presentation fact; the next attempt assumed nested lifecycle rows lived in each direct parent's view. Existing Pager deliberately routes descendant lifecycle rows into the root's flat task display and advances source-child cursors/control independently. Correct the benchmark to that actual existing layout and retain both failed baseline logs; do not change production routing or count failed samples as timing evidence. Star and chain assert exact current row order, flat child identity, source-local state, canonical enrichment and repeat-restore deduplication.

The corrected chain additionally exposed an existing fallback for lifecycle records without `eventId`: repeated descendant restoration can append duplicate task rows because the forced display path has no source-local numeric highwater for those records. The modern producer stamps stable event identities; the benchmark must include those identities and retain the repeat-restore assertion. Keep the failing identityless baseline evidence and record the separate display dedup policy debt instead of changing production identity policy as part of this storage optimization.

Adversarial wire-size check: ACP enforces a64MiB line cap. Optional ownership metadata uses a conservative1MiB JSON-escaped upper bound (six bytes per source byte plus fixed row/envelope cost); oversized results omit the entire optimization and trigger the same validated fallback. Never truncate a map into false empty/partial authority. The cap bounds the added payload, not the rest of an existing response or a new transport protocol.
