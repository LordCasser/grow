## Why

Dashboard 的列表、自动 peek/reply、独立 dispatch 输入和 attached 页面延续了另一套交互模型。普通会话采用新版编辑/翻页/控制流程后，相同 session 会因打开入口不同而改变行为。前一轮修复了运行与页面生命周期故障，尚未消除这些 UX 差异。

## What Changes

仅分析当前源码和已归档契约，按 ui-ux-pro-max 的检索流程提取适用于 Rust TUI 的原则，提出页面职责、目标与焦点、命令语义、状态呈现、用户旅程和分步验收建议。区分已确认的实现、设计判断和未验证风险。

## Capabilities

不修改运行行为、持久化格式、接口或主规范，故 `skip_specs: true`。文中的目标交互是建议，不是已生效契约；后续实施需各自建立行为 delta，不能把设计建议当作已通过的功能验收。

## Impact

只新增本 change 的分析/验证记录及 backlog 索引。不改 UI 代码、不安装字体/前端依赖、不操作真实会话。
