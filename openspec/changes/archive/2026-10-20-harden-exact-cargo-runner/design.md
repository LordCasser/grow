# Design

Run three explicit Cargo phases: `cargo test --no-run` for compilation, `cargo test -- --exact --list` for enumeration, and the existing exact single-thread test invocation for execution. Give compilation, enumeration, and execution separate finite positive timeout values with CLI defaults (60 minutes, 60 seconds, and 15 minutes). The default phase budgets total 76 minutes, within the existing 90-minute CI gate with about 14 minutes of job-level headroom. The 60-minute compile budget is chosen against that gate, not a measured cold-build duration; all phase budgets remain configurable. Existing CLI invocations remain valid; optional flags override each phase.

Launch each command with merged stdout/stderr and stream chunks to the caller immediately. Keep only a bounded output tail for errors and inspect complete lines incrementally for listed test names, pass records, and final summaries. Phase labels go to stderr and include the command's purpose, so Cargo compilation output is associated with the compile phase and listing/parsing errors remain distinct from build failures.

Create a new process session on Unix; on timeout or cancellation, send TERM to its process group, allow a short grace period, then KILL the group and reap the direct child. On Windows, create a new process group and use the built-in `taskkill /PID <pid> /T /F` to terminate descendants, then reap the direct child. A direct-child kill is a fallback if tree termination fails. Bound output-reader shutdown after cleanup. The reader owns and closes its pipe when it exits; the main thread closes it only after the reader has stopped, avoiding a blocking close against a concurrent read. Reader I/O errors are carried back to the caller and treated as phase failures, never as clean end-of-file. If the direct child, termination attempt, or inherited output reader cannot be confirmed within bounded waits, fail with an explicit cleanup-unconfirmed report instead of waiting forever or claiming the tree was terminated. A descendant that escaped its parent's process group or outlived its Windows parent may not be discoverable through these standard mechanisms; the runner reports uncertainty without adding a job-object framework. Re-raise cancellation after cleanup so the CLI reports cancellation and exits nonzero; report whether cleanup was confirmed.

Keep the exact selection invariants: exactly one matching listed test, explicit opt-in for ignored tests, exactly one executed test, and exactly one successful non-ignored pass. Tests should retain parser unit coverage and exercise the streaming runner with a real temporary Cargo/libtest fixture plus real timeout and cancellation process trees, including an escaped descendant that holds stdout after its parent exits. Windows branch tests verify taskkill invocation; the existing Windows storage workflow discovers all `scripts/tests` tests, including the platform-independent real timeout and cancellation fixtures. Actual Windows execution remains an external platform validation.
