# Design

Reuse `.github/workflows/core-regression.yml`, which already runs on pull requests and builds `target/debug/grow`. A serial shell loop selects each backlog test by its full test path with `--exact`, and passes `--ignored --test-threads=1`; `PAGER_BINARY` points every test process at the just-built application. The full paths are verified from each integration target's ignored test list. This avoids invoking `pager_binary()`'s implicit build fallback and avoids running unrelated ignored PTY cases.

The 18 backlog cases belong to five integration targets: minimal (8), config UI (2), scroll selection (2), queue/cancellation (4), and leader fan-out (2). Run the 16 cases from the first four targets and add the separate real-`less` transcript restore case (1), for 17 CI invocations total. Leave both leader tests out of this CI slice: their second turn currently fails to persist its terminal because the event's turn ID does not match the active Timeline turn. The PR run should stay green while that independent behavior regression is fixed; the backlog retains the exact boundary and repro sequence. The runner uses Ubuntu, where these Unix PTY scenarios are supported; install `less` explicitly because that test otherwise returns successfully without exercising its assertions when `less` is absent.

The selected mock-backed fixtures must seed a local provider config after the BYOK startup gate was introduced. Add the seed per scenario before spawn, and make the existing UI config helper append its `[ui]` table instead of overwriting the provider config. Each selected spawn also needs an isolated Git project because the project picker renders over (but does not remove) the minimal idle sentinel; without it, injected test input is consumed before any request reaches the mock. The two leader cases must seed both prerequisites themselves. A Responses fixture retains its explicit backend. No external credentials or paid models are used.

No `#[ignore]` markers are removed. Ordinary Cargo runs remain fast and deterministic; the PR workflow is the required default automated coverage path. Tests are serialized to avoid the multi-process and shared-terminal interference documented by the leader harness.
