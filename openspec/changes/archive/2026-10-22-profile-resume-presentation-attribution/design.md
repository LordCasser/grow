# Design

Reuse existing instrumentation (disabled by default), timers and real CLI/PTY fixtures. Measure CPU service work separately from elapsed replay/writer wait; nested timings are not additive. Preserve trace sequence/timestamps so loading work can be separated from post-ready input tests. A frame written is not proof of emulator visibility; PTY screen sentinels remain the visible endpoint.

Capture a release baseline before changing runtime instrumentation. Compare opt-in instrumentation overhead using the same sources/fixtures and alternate process order; do not present instrumentation as an optimization. Only proceed to independent P1 if full Markdown finalization is a material measured component and has a coherent observationally equivalent lazy-cache implementation. Keep image file observation timing, semantic completion, source text and final layout correctness.

Adversarial checks: missing/zero-test runs, overlapping builds, diagnostic observer overhead, nested totals, wrong transport assumptions, post-ready frame contamination, slow writer sample size, failed writes and partial messages. Retain raw evidence, executable identities, source context, validation outcomes and limitations.
