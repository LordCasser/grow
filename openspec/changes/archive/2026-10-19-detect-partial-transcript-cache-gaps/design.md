# Design

The current selected transcript branch exposes stable `SurfaceId` values. For a user item appended by `Input::Consumed`, the surface ID's event sequence identifies that exact Timeline event, and the user item carries the same `promptIndex` written to ACP `UserMessageChunk` metadata. The offline reader can therefore compare selected-branch prompt indices with the already rewind-filtered updates ledger.

If a selected committed user prompt index has no matching ACP user chunk, projection returns `InvalidData` with the missing index. It does not synthesize content or use update timestamps. Rows for prompts removed from the selected branch are ignored. Timeline events with no prompt index are outside this check because older or host-authored entries may not have a display identity that this mapping can prove.

For Workflow, Goal, Control, and CurrentMode rows, add one compact typed Timeline expectation fact rather than a per-surface cache or actor. It carries the exact UI event ID, projection family, stable source identity, source revision captured when the update is created, and a digest of the serialized update payload. It carries no display body or execution authority. Workflow identity is the run ID; Goal identity is the goal and definition; Control identity includes the epoch, domain, and intent; CurrentMode identity captures the selected behavior at enqueue. Revisions and event IDs distinguish status/mode projections that share a source revision. The projection producer creates the expectation only for a durable row and waits for its Timeline durability acknowledgement before it publishes the row to the physical cache (and live surface). Ephemeral snapshots and updates intentionally coalesced before persistence create no expectation.

Offline reading compares expectations in the captured Timeline frontier against the captured update-ledger frontier by exact event ID and digest. A missing or altered row is incomplete data; timestamps, nearby rows, mutable current state, and manifests cannot satisfy the expectation. The check is read-only and does not synthesize or append rows. A Workflow manifest may help rebuild current runtime state, but it cannot prove which historical projection row was published. Existing Timeline facts without an expectation do not prove that a projection was emitted, so they remain outside this check. Current-format histories that lack expectation facts are not backfilled; unsupported older Timeline formats follow the existing schema-version rejection policy.

On session load, seed the process-global event-ID counter from every parseable numeric suffix in the validated Timeline expectations before replay can be skipped or a fresh actor can publish startup projections. This includes expectations whose cache append was interrupted and IDs from rows later hidden by rewind; neither identity may be reused. The ordinary replay-line high-water seed remains in place for other persisted event IDs.

The user item stored in `Input::Consumed` is the model-facing normalized item, not the bytes shown to the user. The producer emits the raw ordered `prompt_blocks` as one `UserMessageChunk` per block, with both `promptIndex` and `messageId` copied from the accepted ACP prompt. The completeness proof therefore needs a small display fingerprint committed with the consumed input: prompt/message identity, block count, and a digest of the canonical ordered raw block list. Before hashing, recursively sort object keys in the JSON value while preserving array order; JSON object insertion order is not a stable identity. The offline reader groups chunks by that exact message identity and checks the count and digest. This detects a missing block or a truncated block without comparing display content to normalized model input or guessing from timestamps. Accepted steer/interjection inputs use the same fingerprint for their persisted text and image chunks, keyed by their durable input identity and current prompt index. Host-only slash commands do not produce `Input::Consumed` and are outside this mapping.

`TurnCompleted` can be checked without reconstructing its result: persist the original ACP `prompt_id` on `TurnEvent::Started`, then require a matching cached `TurnCompleted.prompt_id` for eligible durably ended turns. The validator reports a missing terminal row and never fabricates a stop reason or result. Recovery-only terminal records without a corresponding user-facing completion remain outside the expected set.

The selected-branch terminal set includes synthetic Workflow/Goal user items materialized by `Notification::Consumed`. Their Turns may have no `input_ids`, but the notification event records the exact `TurnId` and its user item is a selected `SurfaceId` leaf. `TurnStarted.prompt_id` is the original prompt identity and the common settlement producer emits `TurnCompleted` with that same value. The reader must use those typed links; it must not infer a turn from timestamps, nearby prompt indices, or notification order. Timeline also rejects a runtime continuation checkpoint unless its `prompt_id` exactly matches the `TurnStarted` fact for that `turn_id`; `TurnStarted.prompt_id` itself must be non-empty, bounded, and free of control characters.

Workflow and Control rows use the typed expectation mechanism described above. No timestamp or neighboring update is used to infer missing display identity.
