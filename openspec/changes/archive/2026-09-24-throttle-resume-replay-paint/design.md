# Design

Determine whether the currently visible AgentView's session is in `loading_replay`. In that state, use `max(configured_min_draw_interval, 100 ms)` for draw requests generated by ACP state changes, animation deadlines, and periodic UI maintenance. Keep maintenance state updates on their existing clocks; only the paint request is deferred. Leave input and explicit UI actions on their existing immediate paths. The deferred draw still wakes at the computed deadline; the loaded transition uses the normal configured interval so final history and prompt are not held for another 100 ms.

Do not suppress replay notifications or alter the load barrier. This is a paint scheduling policy only. The initial loading frame remains immediate, and automatic progress remains visible at up to ten frames per second. The existing Presenter still allows only one in-flight writer frame, and buffered ACP drains still cut short when input arrives.

Measure against the archived instrumented 128/512-turn PTY fixture with the same binary profile and host. The expected signal is fewer replay-era frame renders and lower time to last visible history without a regression of prompt key echo or lost typed input. If the measured improvement is absent, keep the trace and reconsider the bottleneck rather than increasing throttling further.
