# Verification

- Source trace: `SessionCommand::PublishControlState` runs `publish_completed_hook_projections`; the ChatState actor answers by calling `Timeline::completed_hook_projections`, which scans all Timeline events and clones a projection for each completed occurrence. Shell derives a `HookExecution` update and serializes each one as an individual transient `grow/session_notification`. Pager deduplicates by occurrence ID and attaches tool hooks by call ID; unanchored historical hooks go to the shared compact history block.
- Synthetic measurements ran on Darwin arm64 with rustc 1.98.1 / Cargo 1.98.1, using `CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=2 cargo test --locked --offline -p shell --lib hook_snapshot_scale_probe -- --ignored --nocapture --test-threads=1`. The probe timed ChatState query p50 over 7 samples and full actor-to-mock-gateway publication p50 over 3 samples. It counted exact JSON-RPC `params` bytes emitted by `ExtNotification` (not transport framing). Each occurrence had one skipped handler; the 10,000 unrelated entries were small assistant Message events. No user session data or disk-backed session restore was read.
- Results: 100 Hooks/0 unrelated events: query 64.292 µs, publication 1.830 ms, 100 messages and 27,590 params bytes. 100 Hooks/10,000 unrelated events: query 85.458 µs, publication 2.302 ms, 100 messages and 27,590 params bytes. 1,000 Hooks/0 unrelated events: query 531.375 µs, publication 16.369 ms, 1,000 messages and 276,890 params bytes. The per-occurrence serialized payload stayed near 277 bytes; query time rose when unrelated Timeline events increased, while message count and wire payload did not.
- The focused measurement test passed. Its temporary ignored probe was removed after collecting results; no production code or persistent test harness changed.
- Ordering evidence: `completed_hook_projections` walks Timeline's durable event vector, so returned Hook occurrences preserve Timeline completion order. ACP update replay and Timeline facts use separate ledgers without a shared sequence; the source establishes no total order between them. Client association relies on stable `tool_call_id` and `occurrence_id` identities.
