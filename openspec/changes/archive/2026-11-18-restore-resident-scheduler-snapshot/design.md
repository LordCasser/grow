## Design

The scheduler actor remains the only authority for live task state. `SessionHandle.scheduler_handle` routes a `SchedulerCommand::List`; its `SchedulerSnapshot` already contains the committed version and cloned `ScheduledTask` values, including `last_subagent_id`. The load response projects the task display fields into response metadata after replay. A missing scheduler handle is represented by an absent field.

Pager stores the active scheduler generation, the latest complete snapshot's revision floor, and per-task versions alongside `AgentSession.scheduled_tasks`. The snapshot floor rejects live events older than the complete state it represents; it does not advance when a live event arrives. Live creation, fire, and delete notifications are ordered per task, so a later event for task A cannot block an earlier outstanding event for task B. A newer generation event fences events from older actor epochs and clears the prior epoch's snapshot floor until a complete snapshot from the new epoch arrives. Snapshot adoption merges by task: tasks unchanged since the snapshot are refreshed from it, tasks changed by later notifications retain their newer state, and snapshot absence removes replay-only tasks unless a later notification changed that task. Per-task delete versions act as tombstones so a stale snapshot cannot resurrect a deleted task.

The snapshot is a load-time projection, not another persisted event. Historical Timeline replay remains unchanged. `SchedulerCommand::List` provides the scheduler's serialization point and avoids maintaining a second task map or deriving the latest child from unrelated descendant history.
